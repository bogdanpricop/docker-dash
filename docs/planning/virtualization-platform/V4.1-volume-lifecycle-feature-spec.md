# V4.1 — Volume lifecycle feature specification

**Status:** shipped in v8.22.0 (2026-07-28)

**Release gates:** `DD_PROVIDER_VM_DISK_LIFECYCLE=false` and `DD_PROVIDER_VM_DISK_DELETE=false` by default

**Executable scope:** live disk inventory, create-and-attach, safe detach, grow-only resize, datastore/SR move, managed detached-volume inventory and guarded cleanup

## Outcome

V4.1 turns the portable disk inventory from V1.9 into an operation workflow. An administrator previews every change against fresh provider state, reviews a stable semantic plan, confirms the exact target and submits a durable operation. The operation revalidates immediately before mutation, reconciles the native provider task when one exists, and post-verifies the resulting hardware or backing state.

The common contract never exposes provider-native VM, disk, datastore or task identifiers. A permanent backing deletion is available only for a volume that Docker Dash created, recorded and can still prove it owns. Foreign disks can be detached while retaining their data; they cannot be adopted implicitly or destroyed through the common API.

## User stories

1. An administrator can inspect portable disk identity, bus/unit, capacity, allocation, provisioning, backing, attachment and hot-operation evidence.
2. A create preview validates size, portable bus, unused unit, target storage identity, free-space headroom and provider support before submitting create-and-attach.
3. A detach preview refuses boot, read-only, shared, CD-ROM, snapshot-dependent or otherwise unsafe devices and defaults to retaining the backing volume.
4. Resize is expansion-only. The provider disk is grown first and the result states explicitly that the guest partition/filesystem still needs an operating-system-level expansion.
5. A storage move requires a different target, accessible compatible storage, headroom and no conflicting VM operation. Conversion is not inferred from a move.
6. A detached Docker Dash-owned volume remains in a bounded managed-volume inventory and can be reattached only to its recorded endpoint/VM ownership boundary.
7. Permanent deletion requires the second release flag, exact typed confirmation, a verified recent recovery point, no snapshot/replication dependency and a current ownership proof.
8. Every preview and submission is audited with canonical IDs and bounded non-secret values.

## API

| Method | Path | Access | Effect |
|---|---|---|---|
| `GET` | `/api/providers/:hostId/virtual-machines/:vmId/disks` | host view | live disk inventory plus managed ownership state |
| `POST` | `/api/providers/:hostId/virtual-machines/:vmId/disks/preflight` | admin + host operate | preview create-and-attach |
| `POST` | `/api/providers/:hostId/virtual-machines/:vmId/disks` | admin + host operate | submit create-and-attach |
| `POST` | `/api/providers/:hostId/virtual-machines/:vmId/disks/:diskId/preflight` | admin + host operate | preview detach, resize, move or delete |
| `POST` | `/api/providers/:hostId/virtual-machines/:vmId/disks/:diskId/actions` | admin + host operate | submit the reviewed device action |
| `GET` | `/api/providers/:hostId/managed-volumes` | host view | bounded detached/attached managed-volume inventory |
| `POST` | `/api/providers/:hostId/managed-volumes/:volumeId/delete/preflight` | admin + host operate | preview owned detached-backing deletion |
| `DELETE` | `/api/providers/:hostId/managed-volumes/:volumeId` | admin + host operate | submit reviewed permanent deletion |

| raw Xen over SSH | unsupported | unsupported | unsupported | unsupported | unsupported |

## Release guarantees

- disk, managed-volume and operation IDs are opaque and server generated;
- requested capacity is byte-exact in the plan and rounded only according to an advertised provider allocation unit;
- size shrink is rejected before provider access and again at execution time;
- detach never implies delete, and delete never targets an attached foreign backing;
- boot, shared, read-only and optical devices are permanently excluded from common destructive actions;
- live state, capability, policy, permission, active-operation conflicts and plan hash are revalidated immediately before submission;
- native task absence is accepted only for a documented atomic provider call followed by positive inventory verification;
- managed ownership is recorded only after positive create verification; failed partial creates are surfaced for explicit reconciliation and never auto-deleted;
- `allowed_operations` and hotplug flags are advisory inputs and are re-read before execution;
- the common API never performs in-guest partition or filesystem changes.

## Out of scope

- disk shrink, guest filesystem mutation, encryption-key rotation and guest multipath configuration;
- implicit format conversion, cross-provider disk conversion and cross-endpoint transfer;
- adopting, deleting or garbage-collecting provider volumes not created by Docker Dash;
- bulk delete, wildcard targets, host paths, shell commands or provider CLI fallbacks;
- assuming snapshots are backups or accepting an unverified recovery point as deletion protection.
