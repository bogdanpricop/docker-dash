## Canonical ID

```text
ddr_<kind-prefix>_<26 lowercase hex chars>
hash input = endpoint numeric ID | kind | stable provider UUID/native identity
```

Prefixurile sunt `vm`, `host`, `cluster`, `storage`, `network`, `task`. ID-ul nu poate fi decodat în native ref și nu conține nume/IP/vendor credentials.

## Identity resolution

1. normalizer oferă `uuid`, `nativeRef`, `transient`;
2. identity store caută mai întâi `(host, kind, provider_uuid)`;
3. dacă nu există UUID stabil, caută `native_ref_hash`;
4. la insert, native ref este criptată;
5. la schimbarea ref-ului pentru același UUID, rândul și encrypted ref sunt actualizate;
6. `resolveCanonical()` validează host/kind și decriptează numai intern.

## Normalization policy

- numerele invalide devin `null`, nu `0`, exceptând counters unde zero este semantic;
- timestamp-urile invalide devin `null`;
- state-urile sunt lowercase unde există un mapping sigur; raw state rămâne doar în extension allowlist;
- task result/error sunt trunchiate și nu includ raw XML/JSON;
- labels acceptă maximum 64 keys; key 64 caractere, value 240;
- extensions sunt provider-specific, allowlisted în normalizer, maximum 32 fields;
- relations folosesc canonical ID numai când mapping-ul este cunoscut; altfel un hint safe/UUID.

## Capability-to-kind mapping

| Kind | Capability |
|---|---|
| virtual machines | `inventory.vm` |
| hosts | `inventory.host` |
| clusters | `inventory.cluster` |
| storages | `inventory.storage` |
| networks | `inventory.network` |
| tasks | `inventory.task` |

`conditional` permite listarea; `unsupported` și `unknown` returnează 400 cu reason safe.

## Failure model

- provider unreachable: 502 sanitized;
- invalid provider response: 502 `RESOURCE_NORMALIZATION_FAILED`;
- identity encryption/DB failure: 500 și fără partial untracked IDs;
- item invalid: response-ul complet eșuează în V0.2; partial inventory este amânat până la event/job core;
- over limit: lista este trunchiată determinist și marcată `truncated=true`.

## Rollback

Migrarea este aditivă. Imaginea veche ignoră tabelul 106. Rollback-ul nu necesită DB restore. Rândurile de identity pot rămâne pentru revenirea ulterioară la versiunea nouă.
