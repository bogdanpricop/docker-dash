# V1.3 Feature spec — Common VM snapshot lifecycle

## Obiectiv

Operatorul vede și gestionează snapshot-uri VM printr-un contract comun pentru Proxmox VE, vSphere/ESXi, Xen Orchestra și XenAPI, fără a confunda snapshot-ul cu un backup. Create, revert și delete folosesc identity mapping encrypted, preflight live, confirmare, lock pe VM, task persistent și reconciliation fără replay.

## Scope V1.3.1

- inventar snapshot live și secțiune comună în VM detail;
- ID canonic `dds_snap_*`, native ref encrypted și ownership strict host+VM;
- metadata comună: name, description, createdAt, parent, current, consistency și integrity evidence;
- create crash-consistent pe PVE/vSphere/XO/XAPI;
- create quiesced numai când providerul și guest tools/allowed operations oferă evidence real;
- revert și delete cu preflight separat și typed confirmation;
- maximum snapshot count/chain guard înainte de create;
- child/dependency guard înainte de delete;
- durable handler `vm.snapshot`, native task polling și post-condition verification;
- single-resource API/UI, audit și Activity Center link;
- feature flag implicit off.

## Anti-scope și remapare

- raw Xen/libxl rămâne fără snapshot portabil;
- snapshot memory state nu intră în contractul comun inițial;
- delete subtree/remove-all nu este permis în V1.3.1;
- un snapshot nu este prezentat ca backup, recovery point off-host sau protecție DR;
- scheduler, retention automation și policy CRUD din B126 intră în V1.3.2 după lifecycle canary;
- orchestration guest scripts/VSS fallback din B132 intră în V3.2; V1.3 păstrează doar provider-native quiesce evidence;
- hash de conținut/backup-chain verification din B138 intră în V3.3; V1.3 verifică doar metadata/parent graph și task/post-state.

## Acceptance

- inventarul nu expune MoRef, UPID, UUID/ref Xen sau PVE snapshot key;
- un snapshot canonic nu poate fi folosit pe alt host sau alt VM;
- create cu nume duplicat sau peste limită este blocat înainte de mutation;
- quiesced fără evidence este blocat, nu redus silențios la crash-consistent;
- revert cere numele exact al VM-ului și avertizează că starea curentă este înlocuită;
- delete cere numele exact al snapshot-ului și refuză snapshot cu copii;
- timeout după posibil submit intră în reconcile; handlerul nu repetă mutation-ul;
- create success cere apariția snapshot-ului; delete success cere absența; revert cere task success plus snapshot/VM inventory;
- feature flag `DD_PROVIDER_VM_SNAPSHOTS` este implicit false.
