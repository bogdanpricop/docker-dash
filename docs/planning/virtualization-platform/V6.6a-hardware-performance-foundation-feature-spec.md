# V6.6a — Hardware and performance evidence foundation

**Release:** v8.70.0

**Backlog:** B376–B385

**Date:** 2026-07-30

## Outcome

This batch establishes a normalized, provider-neutral evidence model for host
hardware and workload placement. It supports compatibility and performance-risk
analysis while deliberately exposing no provider hardware mutation endpoint.

## Inventory and compatibility

- Bounded snapshots normalize CPU model/features/topology, NUMA memory and
  hugepages, NICs, HBAs, disks, GPUs, BMC model/firmware and VM placement.
- Every snapshot retains an observation timestamp, source kind, adapter/version,
  declared coverage and SHA-256 evidence identity. Credential-shaped fields and
  documents over 512 KiB fail closed.
- Generated and supplied compatibility tags compare model, generation,
  provider, CPU vendor/features and operational baselines per cluster.
- CPU baseline analysis reports common, union, per-host extra and missing
  features. Unknown/missing evidence is never converted to a supported feature.

## Policy and topology

- The CPU policy editor supports host-passthrough, cluster baseline,
  vendor-compatibility and custom desired modes. vSphere EVC and Proxmox CPU
  model adapters are identified as plan-ready; Xen remains inventory-only and
  unknown providers are explicit unsupported.
- A policy persists its exact desired baseline, blockers, affected hosts,
  preconditions and plan hash. `applyEndpoint` is null and
  `providerMutationsStarted` is permanently zero.
- NUMA topology associates CPUs, memory, hugepages, local devices and VM
  placement. VM fit detects single-node CPU/memory oversizing, cross-node
  pinning and device/guest-NUMA mismatch.

## Performance posture

- CPU pinning distinguishes isolated/dedicated and shared pools, free isolated
  CPUs, unpinned workloads and conflicting assignments.
- The real-time profile checks dedicated CPU, complete pinning, isolation,
  hugepages, latency sensitivity and absence of balloon/swap reclaim.
- Hugepage dashboards aggregate total/free/reserved/allocated capacity by size
  and NUMA node and flag low-free fragmentation.
- Memory posture compares reserved, active, configured, ballooned and swapped
  bytes, computes overcommit/pressure ratios and emits explainable warning or
  critical signals without remediation.

## Persistence and authorization

Migration 144 adds immutable host observations, desired CPU compatibility
policies and two governance permissions. The Hardware & Performance tab is
administrator-only under Governance and every accepted write is audited.
