# V3.3b — Backup control-plane depth (R5a / B129–B138)

## Scope

Acest slice adaugă un contract comun, persistent și fail-closed peste executorul
durabil de backup existent. Acoperă împreună:

- B129: mod `provider|full|incremental` și contract per execuție;
- B130: selecție dinamică după label, stare, site, owner și classification;
- B131: excluderi workload/label/disk/path, fără traducere implicită;
- B132: consistență crash/filesystem/application și referințe de hook allowlisted;
- B133: limite simultane global/provider/host/repository/policy;
- B134: limită de bandă implicită și ferestre site/link/timezone;
- B135: preview GFS normalizat, fără autorizarea ștergerii;
- B136: evidence pentru immutable-until și minimum lock days;
- B137: key reference, algoritm și maximum key age, fără key material;
- B138: verificare separată provider/metadata/checksum/chain.

## Invariante

1. Salvarea, preflight-ul și planul nu pornesc backup.
2. Contractul execuției este legat de `planHash` și are propriul `contractHash`.
3. Nicio referință nativă provider și nicio credențială nu intră în contract.
4. Admission-ul se recalculează înaintea fiecărui child dispatch.
5. Un child în `verification_pending` nu consumă slot de data transfer.
6. GFS rămâne advisory; `retentionMutationAuthorized` este mereu `false`.
7. `required` pentru encryption/immutability/integrity nu poate deveni succes
   pe evidence absentă sau ambiguă.
8. Timeout după submit nu resubmite jobul nativ.

## Persistență

Migrarea `165_provider_backup_control_plane` adaugă:

- `contract_json` pe execuția părinte;
- `admission_json` și `integrity_json` pe child;
- `provider_backup_integrity_evidence`, deduplicat prin hash per child.

Migrarea este aditivă și idempotentă. Down elimină numai tabela de evidence;
coloanele JSON rămân backward-readable și sunt ignorate de imaginile vechi.

## Provider boundary

- Proxmox: executorul real `vzdump` rămâne activ numai după flag, autorizare,
  plan live și typed confirmation. Incremental este admis numai pentru PBS;
  forced-full pe PBS este refuzat deoarece API-ul nu îl dovedește.
- Xen Orchestra: inventory rămâne disponibil. Execuția va fi activată numai
  după discovery explicit pentru un schedule/job task-aware și mapare canonică.
- vSphere: snapshot-ul nu este backup. Execuția necesită un adaptor VADP/VDDK
  sau vendor backup cu data mover, task identity și recovery-point read-back.

## Acceptance

- validare strictă pentru toate câmpurile R5a și lipsa inline scripts/keys;
- contract hash stabil pentru același plan;
- admission-ul blochează la cea mai strictă limită;
- bandwidth-ul alege cea mai restrictivă fereastră aplicabilă;
- integrity evidence este hash-uită, deduplicată și persistată;
- succesul strict cere toate metodele și protecțiile obligatorii;
- UI expune opțiunile fără un buton generic de apply;
- testele focused, lint și regression backup rămân verzi.
