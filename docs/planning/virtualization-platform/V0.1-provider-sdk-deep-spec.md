# V0.1 Deep spec — Provider SDK v2

## 1. Module

```text
src/services/provider-sdk/
  catalog.js          chei și metadata neutră
  schema.js           create/validate/serialize envelope
  registry.js         adaptor registration și lookup
  cache.js            TTL, in-flight dedup și invalidare
  adapters/
    proxmox.js
    vsphere.js
    xen.js
src/routes/providers.js
src/__tests__/provider-sdk-*.test.js
```

Nu se introduce dependency nou. Schema este validată cu funcții pure și teste exhaustive.

## 2. Contractul adaptorului

```js
{
  type: 'xen',
  async probe(context) {},
  declared(context) {},
  normalizeProbe(result, context) {},
  invalidate(hostId) {}
}
```

`context` conține host row și helpers safe. Adaptorul poate folosi serviciul existent, dar nu primește request/response Express.

## 3. Merge evidence

Ordinea de precendență:

1. live evidence explicit;
2. version/edition rule explicit;
3. configuration constraint;
4. adapter declaration;
5. fallback `unknown`.

Un failure de probe nu transformă automat toate feature-urile în `unsupported`. Funcțiile declarate de adaptor rămân cunoscute, dar cele dependente de versiune/backend devin `unknown`.

## 4. Cache

- key: numeric host ID;
- TTL implicit: 60 secunde;
- maximum entries: numărul hosturilor din DB, fără cache global nebounded;
- aceeași probă concurentă este deduplicată prin promise in-flight;
- errors nu sunt cached mai mult de 10 secunde;
- update/delete/reconnect invalidează explicit;
- entry nu păstrează host row cu credential config decriptat.

## 5. Error model

Erorile interne sunt transformate în:

```json
{
  "code": "PROBE_UNREACHABLE",
  "message": "Provider endpoint could not be reached"
}
```

Logul server poate păstra `err.code` și target host ID. Response-ul nu include URL, username, cookie, token, SOAP/XML body ori SSH stderr.

## 6. Provider-specific probing

### Xen

- reutilizează `clientForHost(row).info()` și `capabilities()`;
- variant: `xo`, `xapi` sau `raw`;
- pentru VM, `allowed_operations` rămâne capability per-resource și nu este promovat global;
- `raw/xm` marchează snapshots/tasks/migrate/create `unsupported`;
- XAPI task cleanup este `supported`; XO/raw nu.

### Proxmox

- probe: `/version`, fără mutation;
- inventory VM/LXC/node/storage este `supported` de adaptorul curent;
- snapshot/backup inventory rămân confirmate dacă rutele existente le implementează;
- power/create/migrate/console sunt `unsupported` cu reason „adapter not implemented”, chiar dacă PVE le suportă upstream.

### vSphere

- probe: ServiceContent după login;
- variant: `vcenter` sau `esxi` când poate fi dedusă sigur; altfel `unknown`;
- VM/host/datastore inventory este `supported`;
- datastore browser este extensie vendor;
- power/snapshot/console/migrate/create sunt `unsupported` până la batch-ul dedicat.

## 7. Legacy bridge

`docker.js::_getNonDockerInfo()` poate consuma SDK-ul pentru a construi vechiul map de booleans, dar endpoint-ul existent nu își schimbă forma. Bridge-ul este one-way; noul model nu este derivat din legacy după migrarea adaptorilor.

## 8. Security invariants

- registry acceptă doar daemon types din allowlist;
- feature keys vin numai din catalog;
- constraints sunt JSON-safe, bounded și fără funcții/prototype keys;
- maximum response size intern: 256 KiB;
- maximum reason: 240 caractere;
- timestamps sunt ISO UTC generate server-side;
- host ID vine din path și host access middleware, nu din body;
- refresh are rate limit și admin role.

## 9. Observability

Metrics propuse:

- `dd_provider_probe_total{provider,status}`;
- `dd_provider_probe_duration_seconds{provider}`;
- `dd_provider_capability_cache_total{result}`;
- `dd_provider_capability_unknown{provider}`.

Fără endpoint URL, host name sau user în labels pentru a evita cardinality și leakage.

## 10. Compatibilitate și rollback

- fără migrare DB în V0.1;
- route nouă, aditivă;
- feature flag poate dezactiva route-ul;
- codul legacy rămâne funcțional;
- rollback înseamnă redeploy imaginea precedentă, fără DB restore.
