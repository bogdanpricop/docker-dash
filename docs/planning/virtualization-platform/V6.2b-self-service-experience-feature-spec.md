# V6.2b — Accessible and explainable self-service experience

**Release:** v8.69.0

**Backlog:** B366–B375

**Date:** 2026-07-30

## Outcome

This batch completes the self-service backlog with time-bound capacity requests,
safe organization branding, contextual support, explainability, responsive
incident handling, accessibility, localization completeness and opt-in local
feedback. Existing provider execution and approval boundaries remain unchanged.

## Capacity, branding and guidance

- Project administrators submit bounded quota changes to the existing approval
  engine. Approval creates an expiring grant; rejection or expiry never changes
  the base quota.
- Organization branding can be overridden per project and inherited otherwise.
  Accent colors are normalized and logo/help links must be same-origin or HTTPS.
- Help topics select provider, reported version and action caveats and always
  offer a non-mutating next safe test.
- Troubleshooting stores an evidence checklist plus a SHA-256-bound support
  bundle. Request values, fabric references, users, URLs, credentials, raw errors
  and stack traces are excluded.

## Explainability and safe operations

- Recommendations expose reason, evidence and evidence hash, confidence basis,
  expected impact, suggested non-mutating action and undo guidance.
- Self-service tabs and VM action controls support semantic keyboard navigation,
  labelled controls and polite live-region status announcements.
- The responsive incident view combines self-service request failures/running
  jobs and authorized administrative alerts. Mobile actions are limited to
  acknowledge and temporary notification pause and never mutate infrastructure.

## Quality and privacy gates

- Critical provider/action/safety strings are required in all 11 bundled
  languages; placeholder mismatches fail CI.
- The accessibility gate covers semantic tabs, operation labels, live regions,
  visible focus, contrast modes, reduced motion and 44-pixel mobile targets.
- Feedback is disabled by default and requires per-user opt-in. Only allowlisted
  event, outcome and provider counters are aggregated locally per day. Exact
  payload and exclusions are visible before opt-in; no collector or network
  transmission exists.

## Persistence and authorization

Migration 143 adds branding, help, troubleshooting, incident preference and
feedback aggregate tables plus four dedicated governance permissions. All
reads remain project-scoped and all writes require the corresponding inherited
or administrative permission.
