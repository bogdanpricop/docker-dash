# V1.1 Deep spec — Common VM detail

## DB migration 109

`provider_resource_snapshots` păstrează doar resursa normalizată și publică:

- `canonical_id` FK către identity store;
- host/provider/kind/display name/power state;
- `resource_json`, maximum logic 64 KiB per item;
- `observed_at` și `updated_at`;
- index host/kind/name și observed time.

Native refs și credentialele rămân exclusiv în identity/config encryption stores.

## Refresh și cache

1. list inventory normalizează și upsert-ează snapshot-uri într-o singură tranzacție;
2. detail caută ID-ul în cache;
3. `refresh=true` sau cache miss rulează inventory bounded (max 500) și reîncearcă;
4. un ID din alt host/kind este 404, fără a dezvălui existența;
5. response maxim 512 KiB.

## Action explanations

Blockers posibili:

- `CAPABILITY_UNSUPPORTED` / `CAPABILITY_UNKNOWN`;
- `RESOURCE_STATE_BLOCKED`;
- `RESOURCE_ACTION_BLOCKED`;
- `POLICY_BLOCKED`;
- `PERMISSION_BLOCKED`;
- `ACTION_NOT_ENABLED` — obligatoriu în V1.1.

`reason` vine din evidence sanitizat și este limitat. Nicio acțiune nu este prezentată available până la V1.2.

## UI

- `#/virtual-machines`: host selector și common VM cards;
- `#/virtual-machines/:hostId/:canonicalId/:tab`: `DetailShell` cu tab deep links;
- disabled action buttons au tooltip cu blocker-ele;
- unavailable sections afișează reason și capability key;
- command palette folosește snapshots DB și host permissions.

## Failure și rollback

- provider offline: cache-ul poate fi afișat cu stale marker; refresh error nu șterge snapshot-ul;
- cache JSON corupt/oversized: item-ul este ignorat și detail încearcă refresh;
- migration 109 este aditivă; V0.4 ignoră tabelul;
- rollback păstrează snapshots, iar identity cascade rămâne autoritativ.
