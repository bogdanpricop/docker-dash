# V6.3c / V5.6a — Sustainability and KubeVirt convergence

**Release:** v8.62.0
**Backlog:** B296–B305

## Delivered scope

1. Normalize power observations from BMC, vendor, meter, manual or import
   sources into bounded host/site intervals with watts, kWh and provenance.
2. Calculate fleet energy, W/VM, W/workload, low-utilization waste, carbon
   emissions and factor coverage without treating missing evidence as zero.
3. Configure time-bounded site/region carbon factors with credential-free HTTPS
   sources, methodology and immutable hashes.
4. Rank carbon-aware site/time candidates only after capacity, residency, SLA,
   latency and factor-evidence blockers are evaluated.
5. Compare 1–120 month TCO options using CAPEX, recurring cost families,
   migration, residual value, discount, escalation, carbon price and risk.
6. Discover KubeVirt, CDI, migration, snapshot, console, OpenShift, Harvester,
   Longhorn and network-attachment APIs using group and CRD evidence.
7. Normalize VirtualMachine, VirtualMachineInstance and migration identity,
   desired/observed state, node, interface and migration history.
8. Expose OpenShift projects/routes/operator conditions/namespace RBAC and
   Harvester images/networks/backups/Longhorn volume state as read-only views.
9. Persist explicit capability and inventory snapshots with bounded payloads
   and idempotent evidence hashes.
10. Provide a VirtualMachine-only YAML editor with local structural checks,
    identity/status/inline-secret guards, unified diff and Kubernetes
    `dryRun=All` server validation.

## Safety boundary

- Sustainability results create no schedules, migrations, purchases, invoices
  or billing transactions.
- KubeVirt discovery and platform adapters are read-only.
- YAML validation has no Apply route. Every result persists `applied=0` and
  records the server response, source/desired hashes and diff.
- Missing or forbidden API evidence is `unknown`, never inferred as supported
  or safely writable.
- Existing Kubernetes bearer tokens remain encrypted in daemon configuration
  and are never returned by these APIs.

## Verification contract

- Migration 136 creates seven additive evidence stores and three permissions.
- Unit tests cover calculations, idempotency, constraints, discovery coverage,
  normalization, adapter evidence, secret rejection and accepted/rejected
  server dry-runs.
- Full Jest, ESLint, browser syntax, database migration/integrity and external
  authenticated-boundary smoke tests gate the production rollout.
