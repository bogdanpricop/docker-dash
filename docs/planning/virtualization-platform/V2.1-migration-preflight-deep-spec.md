# V2.1 — Migration preflight deep spec

## Flow

`vm-migration-preflight.preflightForHost()` refreshes host-scoped VM and host inventory, reads optional device topology, resolves encrypted native identities, and calls `registry.migrationCompatibilityForHost()` through the provider resilience boundary. The service then applies common health/capacity gates, normalizes provider evidence, scores candidates, and returns a bounded envelope.

## Provider evidence

- Proxmox: migration precondition endpoint, QEMU/LXC config, target node storage and bridge inventory.
- vSphere/vCenter: VM runtime host plus `QueryVMotionCompatibility` CPU/software evidence; generic host state, maintenance, and memory gates remain independent.
- direct XAPI: `VM.get_possible_hosts`, `VM.assert_can_boot_here`, resident host, and allowed operations.
- Xen Orchestra: same-pool host topology and capacity heuristics, labeled low confidence when no dry-run API is available.
- standalone `xl`/`xm`: no multi-host management plane, therefore no target candidates.

## Contract boundaries

- maximum 64 targets, 64 checks per target, and 512 KiB response;
- target IDs are existing canonical `ddr_host_*` identifiers;
- provider faults become bounded codes/reasons, never raw credential-bearing text;
- `vm.migrate` remains unsupported until V2.2;
- cross-endpoint/cross-provider candidates are not silently mixed into this plan.
