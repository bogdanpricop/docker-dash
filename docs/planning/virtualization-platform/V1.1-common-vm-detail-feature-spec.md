# V1.1 Feature spec — Common VM detail

## Obiectiv

Operatorul navighează la aceeași pagină VM pentru Proxmox, vSphere și Xen. Modelul și shell-ul sunt vendor-neutral, iar lipsurile sunt explicate prin capability evidence, policy, state și permission blockers în loc să dispară silențios.

## Scope

- cache persistent numai pentru snapshot-ul public normalizat al resursei;
- listă VM comună per endpoint și deep link cu ID canonic opac;
- detail envelope `1.0` cu overview, hardware, guest, placement, ownership și health;
- tab-uri consistente: Overview, Hardware, Disks, Network, Snapshots, Tasks, Events;
- secțiuni indisponibile cu reason/evidence, fără a simula paritate;
- action availability matrix pentru power operations, read-only în V1.1;
- activitate din durable provider operations și deep link către Activity Center;
- pagină „Virtual Machines” cu provider/host selector;
- rezultate VM în command palette din cache, fără network fan-out;
- host access și secret/native-ref isolation.

## Anti-scope

- nicio acțiune VM comună; power mutation intră în V1.2;
- nicio inventare falsă de disks/NICs dacă adapterul nu le expune;
- nicio consolă, snapshot mutation sau provisioning;
- snapshot-ul public nu înlocuiește inventory live și nu conține native refs.

## Criterii de acceptare

- aceeași schemă detail pentru cei trei provideri;
- canonical VM ID este singurul identificator din URL/API;
- snapshot cache persistă numai modelul deja sanitizat;
- fiecare tab are `available`, `reason`, `capability` și `items/data` bounded;
- toate acțiunile V1.1 sunt disabled și explică blocker-ul;
- viewer vede detail doar pentru host-uri permise;
- command palette caută VM-uri fără apel provider;
- UI poate naviga list→detail→provider page și păstrează deep-link-ul tabului;
- staging ESXi validează listă, detail, cache, search și UI smoke.
