# V1.4 Deep spec — Activity Center and native task bridge

## Contract public

Schema 1.0 rămâne backward-compatible. Fiecare operation envelope primește:

```json
{
  "owner": { "type": "user", "id": 7, "username": "operator" },
  "permissions": { "canCancel": true, "canResolve": false }
}
```

`owner.type=system` are ID și username `null`. `permissions` este adăugat la nivel de route după role + effective host access; engine-ul nu ia decizii de autorizare HTTP. `get/list` fac `LEFT JOIN users`, fără migrare și fără schimbarea ownership-ului persistent.

## Cancel

UI oferă cancel numai pentru `queued`, `running`, `waiting_retry` și `reconciling`. Endpoint-ul revalidează rol admin/operator și host `operate`. Pentru o operație deja dispatch-uită, confirmarea cere operation ID exact și explică faptul că providerul poate refuza anularea.

Engine-ul păstrează semantica existentă:

- queued înainte de dispatch poate deveni local `cancelled`;
- handler cancel confirmat devine `cancelled`;
- anularea neconfirmată, eșuată sau ambiguă devine `unknown` și păstrează lock-ul;
- starea provider/inventory este autoritativă, nu click-ul din UI.

## Resolve unknown

Butonul este publicat doar pentru admin când state este `unknown`. Dialogul cere resolution, evidence bounded și operation ID exact. Endpoint-ul și engine-ul revalidează toate câmpurile; doar după update-ul condiționat `WHERE state='unknown'` se eliberează locks și se adaugă event/audit.

## Native task projection

Activity Center arată numai `hasNativeTask` și `nativeTaskState`. MoRef, UPID, XAPI/XO task refs rămân AES-256-GCM encrypted și nu sunt returnate. Timeline-ul public arată stare, phase, progress și mesaje bounded/redacted.

vSphere descrie Task ca mecanismul pentru monitorizarea și posibila anulare a operațiilor lungi; `TaskInfo` separă explicit `cancelable`, `state`, `progress` și timestamps. XAPI avertizează că anularea poate eșua sau poate dura arbitrar și că progress nu trebuie folosit pentru a decide completion. Proxmox păstrează operațiile ca task-uri identificate prin UPID. Contractul comun păstrează aceste diferențe în adapter/handler și nu promite o anulare universală.
