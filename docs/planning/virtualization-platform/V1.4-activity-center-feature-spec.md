# V1.4 Feature spec — Activity Center completion

## Obiectiv

Activity Center devine suprafața operatorului pentru toate operațiile Provider SDK: owner și task bridge vizibile fără raw provider refs, căutare și deep links, cancellation request capability-scoped și rezoluție manuală fail-closed pentru rezultate `unknown`.

## Context

V0.3 a livrat engine-ul persistent, idempotency, locks, leases, timeline, cancel/resolve API și policy controls. V1.2/V1.3 au legat operațiile power și snapshot de task-urile native. Gap-ul V1.4 este în principal contractul de prezentare și operarea sigură din UI, nu un al doilea job engine.

## Scope

- owner public explicit (`user` cu ID/username sau `system`), fără a expune credentiale;
- permisiuni derivate server-side `canCancel` și `canResolve` pe fiecare operație;
- căutare locală în setul host/state-filtered după operation, VM, action, provider și owner;
- native-task presence/state, duration, attempts și timeline îmbogățite;
- cancel button numai pentru stări requestable și rol/host `operate`;
- avertisment că anularea poate eșua sau poate termina într-o altă stare validă;
- manual resolution numai pentru admin + `unknown`, cu evidence și confirmarea exactă a operation ID;
- rânduri accesibile prin tastatură și deep-link stabil;
- raw native task ref, worker owner, lease și lock scope rămân ascunse.

## Acceptance

- list/detail returnează acțiuni permise calculate de server, nu deduse exclusiv din rol în browser;
- viewer nu vede cancel, operator fără `operate` nu vede cancel, admin vede resolve numai pentru `unknown`;
- `cancel_requested` nu mai oferă încă un buton de cancel;
- cancellation response nu declară succes până la confirmarea handler/provider;
- resolve cere una din `succeeded/failed/cancelled`, minimum 8 caractere evidence și typed operation ID în UI;
- owner username vine prin join read-only și operațiile system au owner explicit;
- native refs criptate nu apar în list/detail/timeline;
- WebSocket refresh și host/state filters existente rămân funcționale.
