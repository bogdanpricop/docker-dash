# V0.3d — Automation operations and lifecycle readiness

**Release:** v8.57.0  
**Backlog:** B246–B255  
**Date:** 2026-07-29

## Outcome

V0.3d closes the automation/GitOps research section and establishes the first
lifecycle/update contracts. Timers, approvals, simulations, broker access,
catalog ingestion and prechecks persist evidence only. They neither synthesize
an arbitrary provider request nor start a workflow, apply, package install or
upgrade implicitly.

## Data model and permissions

Migration 131 adds twelve additive tables: schedule definitions/runs, timed
approvals, provider dry-run evidence, secret broker profiles/access events,
curated workflow templates, version inventory, support registry, upgrade paths,
update catalog and upgrade prechecks. It seeds five versioned curated templates
and adds `infrastructure_operations.manage` plus `lifecycle_updates.manage` to
the site-admin catalog. The initial API remains administrator-only.

## Timer and approval behavior

The automation timer is singleton and HA leader-gated. A due schedule records
`ready`, `holiday_suppressed` or `blackout_suppressed`, keyed uniquely by UTC
minute. It intentionally does not call a workflow runner. Approval sweeps move
`pending → escalated → expired` when configured, or `pending → expired`; manual
decisions require the stored SHA-256 payload hash and current assignee.

## Secret and adapter behavior

Broker profiles contain provider kind, opaque reference, allowlisted purposes
and a lease ceiling of 300 seconds. The fetched value is never persisted or
returned. A consumer receives a temporary buffer, which is zeroed in `finally`;
access evidence contains outcome and a truncated SHA-256 fingerprint. Only the
environment adapter is built in and it accepts the `DD_BROKER_SECRET_*`
namespace. Vault/cloud providers stay explicitly unavailable until a dedicated
adapter is registered.

Dry-run adapters are similarly explicit and injectable. A provider without a
registered validate/simulate implementation produces durable `unsupported`
evidence. Adapter input/output is bounded and rejects secret-shaped fields.

## Lifecycle readiness behavior

Lifecycle sources must be HTTPS and credential-free. Inventory older than 24
hours blocks advice/precheck readiness. Upgrade paths are exact and retain
vendor hops, prerequisites and known blockers. Catalog ingestion accepts only
`official_vendor` and canonicalizes each entry into a digest. Prechecks expire,
evaluate all six evidence categories and have no upgrade execution method.

## Verification

Dedicated tests cover all ten backlog contracts, the twelve exact stores, two
permissions, five template seeds, calendar suppression/deduplication, approval
escalation/expiry/hash binding, supported and unsupported dry runs, broker
zeroization/audit, template DAG instantiation, inventory upsert/secret rejection,
support derivation, path advice, idempotent official catalog ingestion and both
ready/blocked precheck results.
