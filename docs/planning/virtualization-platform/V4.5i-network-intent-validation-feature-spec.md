# V4.5i — B125 network intent validation

## Status

Implementation in progress on 2026-07-30. The validator is local, immutable,
hash-bound and has no network/provider apply path.

## Contract

`POST /api/governance/lifecycle/network-advanced/intent-validations` accepts a
bounded intent containing:

- scope and caller-owned intent version;
- global inventory completeness and explicit requirements;
- up to 200 networks with IPv4/IPv6 CIDRs, gateways, DNS, routes, VLAN/VNI,
  fabric/L2 domains and source evidence;
- up to 500 reserved CIDRs with owner identity.

It returns normalized intent, bounded findings, `intentHash`, immutable
`validationHash`, and one verdict: `pass`, `fail`, or `unknown`.

## Checks

- strict IPv4 and IPv6 parsing and canonical network boundaries;
- gateway membership and IPv4 network/broadcast exclusion;
- DNS rejection for unspecified, multicast and broadcast addresses;
- route destination canonicalization, next-hop on-link evidence, duplicate and
  conflicting exact routes;
- intra/cross-network CIDR overlap and reserved-range ownership conflict;
- duplicate gateway identities;
- VLAN collision inside the same L2 domain and VNI collision inside the same
  fabric;
- required gateway/DNS/VLAN/VNI presence;
- global inventory and per-network evidence completeness/freshness.

Malformed input returns a typed validation error. A well-formed conflicting
intent is persisted with `fail`. Incomplete evidence is persisted with
`unknown`; it can never become `pass` by omission.

## Execution boundary

The endpoint starts zero provider mutations and performs no network calls. The
result declares `acceptableVerdict: pass`; future R8 network executors must
bind the exact `intentHash` and `validationHash` and reject any other verdict.
No executor is added by this slice.
