# V0.3 Assumption audit

| ID | Presupunere | Verificare | Rezultat local |
|---|---|---|---|
| O01 | SQLite transactions sunt suficiente pentru claim/locks într-un singur app DB | concurrent claim tests | confirmat cu atomic multi-lock |
| O02 | toate viitoarele provider mutations pot furniza idempotency key | V1 route specs | acceptat ca invariant |
| O03 | handler-ul poate distinge transient de permanent | error catalog + tests | închis: allowlist + `transient=true`; permanent nu are retry |
| O04 | timeout nu înseamnă failure | reconcile-first state tests | închis: timeout→reconciling sau unknown |
| O05 | native task refs pot conține date sensibile | ciphertext test | închis: AES-256-GCM și API omission |
| O06 | process restart poate apărea în orice phase | expired lease recovery | închis: running→reconciling, cancel rămâne cancel flow |
| O07 | lock scope poate fi derivat înainte de execute | handler registration contract | acceptat |
| O08 | dynamic read-only trebuie să poată fi dezactivat în read-only | policy route exception + admin audit | închis: policy route este recovery exception admin-only |
| O09 | legacy workers nu pot fi convertiți în același batch | no-shape-change/full suite | acceptat, migration incremental |
| O10 | WS delivery nu este sursă de adevăr | DB poll tests | acceptat |
| O11 | HA multi-replica necesită owner token și lease, nu in-memory lock | two-engine fixture | confirmat: un singur owner execută handler-ul |
| O12 | VPS poate rămâne blocat fără a opri staging batches | deploy journal | acceptat explicit |
