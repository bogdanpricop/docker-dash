# V4.1 — Volume lifecycle assumption audit

| Assumption | Counterexample | Contract decision |
|---|---|---|
| detach means delete | Proxmox turns a detached disk into `unusedN`; vSphere remove can retain its file | retain is the only detach semantic; delete is separate |
| an opaque disk ID proves ownership | V1.9 IDs prove stable correlation, not who created the backing | persist a separate managed-volume ownership record |
| every unreferenced volume is safe to delete | backup chains, templates or another VM may reference it | never adopt/clean foreign volumes heuristically |
| a larger virtual disk expands the guest | partition and filesystem remain unchanged | return mandatory guest-expansion guidance |
| resize is reversible | most providers cannot safely shrink a virtual disk | shrink is permanently rejected |
| `allowed_operations` cannot change | XenAPI documents it as advisory current state | re-read immediately before submit |
| hotplug is uniform per provider | controller, guest state and per-device flags differ | gate per VM/device and current power state |
| moving storage can convert format safely | provider defaults and datastore type may change behavior | no implicit conversion; B082 remains fail-closed |
| snapshots protect deletion | snapshots share the failure domain and may depend on backing | snapshot dependency blocks; verified recovery point required |
| free bytes alone make placement safe | thin provisioning and concurrent consumers can exhaust storage | include configurable headroom and overcommit warning |
| boot disk is obvious from device order | firmware/controller order and provider metadata can differ | require positive non-boot evidence for destructive action |
| shared/read-only flags are always known | provider APIs can omit them | unknown safety evidence blocks deletion |
| a successful HTTP response proves mutation | many APIs return an async task or accept config before failure | reconcile task and post-read exact state |
| failed create can be retried safely | retry may create a second backing | no replay; preserve partial ownership state |
| provider-native refs can be sent to the browser | refs may expose inventory topology and enable confused-deputy requests | only canonical IDs cross the route boundary |

## Audit probes

1. Reject shrink, equal-size resize, fractional/unsafe byte sizes and capacity beyond provider maximum.
2. Reject detach/delete of boot, optical, shared, read-only and ambiguously classified disks.
3. Prove a foreign disk cannot be permanently deleted, even with both flags enabled.
4. Prove detach never adds a provider file-destroy/delete-backing instruction.
5. Prove delete requires an owned detached volume, fresh verified recovery point and exact phrase.
6. Prove stale plan hash, changed disk capacity/storage, active VM operation and changed capability all block submission.
7. Prove create reserves one device slot and rejects ambiguity after post-read.
8. Prove online resize is rejected unless the current device/provider evidence explicitly permits it.
9. Prove native task success without post-read evidence does not become a successful operation.
10. Prove route responses/audit events contain no native disk, storage, VM or task references.
11. Prove Xen Orchestra/raw Xen fail closed without falling back to shell or undocumented RPC.
12. Prove managed record transitions and tombstones survive restart and do not cascade-delete audit history.
