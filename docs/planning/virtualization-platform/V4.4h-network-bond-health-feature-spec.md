# V4.4h — Bond/LAG health observations

**Backlog:** B121
**Status:** local implementation and vSphere standard-vSwitch collector complete; live/distributed/non-vSphere evidence and browser pending
**Scope:** passive normalized bond/team/LAG health evidence

## Outcome

Administrators can import immutable Bond/LAG observations across provider and
host implementations. The service evaluates member availability, minimum active
membership, active/standby semantics, LACP participation/partner consistency,
speed/duplex mismatch, error/drop deltas, link flaps, recent failover evidence
and traffic imbalance.

## Evidence contract

- A batch identifies source, provider host, observation/expiry and coverage.
- Each bond declares host, mode, minimum active members, observation interval,
  imbalance threshold and bounded members.
- Member evidence contains admin/link state, explicit role, speed, duplex,
  LACP partner key and traffic/error/drop/flap deltas.
- Active membership is never inferred solely from `link=up`; role must be
  explicit for active/backup and aggregation modes.
- LACP partner consistency is evaluated only from explicit partner evidence.
- Imbalance is evaluated only when at least two active members carry observed
  traffic. Zero traffic is `not_observed`, never proof of balance.
- Incomplete, expired or unknown critical evidence remains `unknown`.

## Persistence and UI

- Normalized inputs and calculated findings are immutable, bounded and
  SHA-256 deduplicated.
- Admin-only audited ingestion is exposed under Network Advanced.
- UI shows overall state, mode, active/required members, LACP partner state,
  imbalance spread, failover count and warning/failure totals.
- The vSphere adapter reads pNIC, standard-vSwitch, MTU, teaming policy and
  active/standby order through PropertyCollector. Missing traffic deltas,
  partner state, flaps and failover history force incomplete coverage rather
  than a healthy result.

## Safety

- No packet, link toggle, bond reconfiguration, failover, provider mutation,
  guest command or remediation is started. The explicit capture action performs
  bounded read-only interface inventory.
- Distributed-switch/LACP depth and Proxmox/Xen collection remain separate
  read-only integrations.
- Existing PF/VF inventory remains authoritative for B122 and is not duplicated.

## Acceptance evidence

- active-backup and LACP healthy/degraded cases;
- active-member quorum failure and LACP partner mismatch;
- speed/duplex/errors/flaps and load-spread findings;
- zero-traffic imbalance remains not observed;
- incomplete/expired evidence, strict inputs and dedupe;
- API audit, UI contract, focused tests, lint and registry reconciliation.
