## Safety contract

- All live Kubernetes collection uses GET except VM GitOps validation, which
  submits the complete `kubevirt.io/v1 VirtualMachine` only with `dryRun=All`.
- VM identity and server-owned status are immutable in the planner. Repository
  URLs must be credential-free HTTPS, repository paths are relative, and
  secret-shaped manifest/profile fields are rejected.
- GitOps plans record desired/live hashes, dry-run acceptance and redacted
  controller status. They expose no apply, reconcile or delete action.
- Admission evaluations are hash-idempotent and the schema fixes `enforced=0`.
- Cluster plans contain only opaque registered references, explicit uncollected
  prechecks and `provider_mutations_started=0`; there is no provider executor.
- Provenance says `externally_verified` only when the caller supplies verifier
  and timestamp evidence. Docker Dash does not claim to verify signatures.
- Topology, metrics and persisted JSON are bounded; secrets and credentialized
  URLs are not retained.

## Persistence and authorization

Migration `138_unified_kubernetes_platform.js` adds nine evidence, plan,
catalog, provenance, modernization and application-environment tables. It seeds
five VM admission policies, five curated cluster workflows and four site-admin
permissions. The permission catalog total becomes 57.

## Verification target

The focused suite covers all ten backlog items, including topology relations,
quantity conversion, contention, RBAC/API coverage, controller redaction,
timestamp-independent deduplication, dry-run-only planning, inline-secret and
credential URL rejection, non-enforcement, blocked cluster plans, modernization
blockers, provenance trust semantics and component/host validation. Full Jest,
ESLint, syntax and migration verification are required before tag and rollout.
