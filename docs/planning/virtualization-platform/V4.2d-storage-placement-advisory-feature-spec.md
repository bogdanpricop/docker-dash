# V4.2d — Storage placement advisory feature specification

**Status:** shipped in v8.26.0 (2026-07-28)

## Outcome

Storage Posture evaluates provider-visible storage targets for a requested
virtual-disk size. The advisory applies the same configured capacity headroom
as VM disk lifecycle preflight, but does not reserve capacity or authorize a
write operation.

## Safety contract

1. The endpoint is host-view scoped and gated by `storage.placement.read`.
2. A target is a **candidate** only when every applicable observation passes:
   accessibility, normalized maintenance state, requested capacity plus
   headroom and, for Proxmox, VM disk-image content support.
3. Missing or unrecognized accessibility, maintenance, content or capacity
   evidence is **unknown**, never a candidate. A negative observation blocks
   the target.
4. Requested size is bounded to an integer between 64 MiB and 64 TiB. Storage
   inventory remains bounded to 500 normalized targets.
5. The advisory is point-in-time evidence only. It performs no reservation,
   write/test-write, disk creation, provider shell fallback or automated
   placement; execution must run its own fresh preflight.

## API

| Method | Path | Access | Effect |
|---|---|---|---|
| `GET` | `/api/providers/:hostId/storage-placement-advisory?requiredBytes=…` | host view | bounded live read-only target evidence |

## Explicit exclusions

- capacity reservation, quota/chargeback accounting and concurrent placement coordination;
- QoS, multipath, datastore policy remediation or storage mutation;
- claiming compatibility with guest filesystems, clustered applications or a future VM placement.
