# V4.2h — B096 assumption audit

| Assumption | Failure mode | Decision/evidence |
|---|---|---|
| Open TCP 2049/445 proves repository health | false green while export/share auth or listing fails | TCP is only one stage; absent auth/list evidence yields `unknown` |
| The app container can mount remote filesystems | persistent mount, CAP_SYS_ADMIN expansion, cleanup leak | built-in adapter never mounts; protocol stages are pluggable and explicit |
| Credentials may be embedded in a UNC/URL | audit/API/log credential leak | schemes, UNC and credential-shaped fields are rejected; only vault `secretId` is stored |
| DNS may be resolved again during connect | DNS rebinding changes the target | TCP uses the bounded address returned by the same probe resolution |
| Public destinations are the only safe SSRF policy | legitimate private NAS targets become unusable | admin-only registry allows private unicast; invalid/unspecified/multicast/broadcast targets are blocked |
| A scheduler may perform harmless writes | repeated files and unexpected storage mutation | scheduler is read-only; write test is manual, disabled by default and typed-confirmed |
| Successful write means successful test | marker remains when cleanup fails | cleanup proof is mandatory; failure is critical and alertable |
| Raw socket errors are safe API details | local topology/path disclosure | public evidence contains stable stage codes only |
| Every failure should notify | alert storms | first baseline is silent and only worsening transitions notify |
| A secret reference implies valid authentication | stale/rotated/wrong credential | auth remains unknown until an approved adapter checks it; secret value is never returned |
