# V3.1 — Assumption and evidence audit

| Assumption considered | Decision | Evidence/control |
|---|---|---|
| a VM snapshot can be shown as a backup | rejected | only provider backup repository/archive collections enter V3.1 |
| a listed archive is healthy | rejected | verification defaults to `unknown`; V3.3 owns active verification/log correlation |
| PBS capability proves a point was encrypted or protected | rejected | repository capability and per-point state are separate tri-state fields |
| XO REST has full legacy API parity | rejected | runtime OpenAPI discovery gates the two required modern collections |
| direct XAPI exposes XO backups | rejected | XAPI/raw Xen are typed unsupported; no private JSON-RPC fallback |
| vSphere snapshots provide backup inventory | rejected | vSphere is unsupported until a backup manager integration is configured |
| one PVE row per node means multiple backups | rejected for shared storage | shared `volid` values are de-duplicated; local stores remain node-scoped |
| an absent VM makes its backup irrelevant | rejected | orphan/unmapped points remain visible and are counted explicitly |
| repository URLs are harmless metadata | rejected | XO URL is not requested; PVE storage configuration is not read |
| provider strings can be sent directly to the browser | rejected | text/count/size bounds, canonical IDs, encrypted native refs and output escaping |
| a provider name equal to its native key can always be hidden | qualified | user-facing repository names are retained; path/URL/archive identity fields are never returned |
| V3.1 completes retention/encryption/verification workflows | rejected | it only observes explicit evidence; policies/actions remain V3.2/V3.3 |

## Residual risks

- Provider versions can change response shapes despite route continuity; fixtures and endpoint conformance must expand as real XO/PBS endpoints become available.
- PVE content rows may omit verification/encryption state even when PBS holds richer metadata. V3.1 remains conservative rather than calling PBS directly with new credentials.
- Workload mapping depends on prior canonical inventory observation. An unmapped point is safe and visible, but a later inventory refresh may improve correlation only on the next recovery-point read.
- A display label can itself contain operationally sensitive text chosen by an administrator. Host access control and HTML escaping apply; V3.1 does not redact legitimate object names.
- Active verification, restore testing and RPO/RTO compliance are not inferred from inventory and remain subsequent batches.
