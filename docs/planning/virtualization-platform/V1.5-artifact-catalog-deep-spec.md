# V1.5 Deep spec — provider artifact catalog

## Contract

`inventory.image` este capability-ul comun pentru artefacte deployable. Inventory-ul general rămâne limitat la VM/host/cluster/storage/network/task; catalogul separat evită schimbarea CHECK constraints și semanticile resource snapshots existente.

Envelope `1.0`:

```json
{
  "schemaVersion": "1.0",
  "provider": { "type": "xen", "endpointId": 7 },
  "observedAt": "ISO-8601",
  "count": 1,
  "totalObserved": 1,
  "truncated": false,
  "filters": { "kind": null, "query": null },
  "items": []
}
```

Un item conține numai câmpuri bounded: `kind`, `id`, `displayName`, `description`, `createdAt`, `provider`, `identity`, `provenance`, `spec`, `labels`, `observedAt`.

## Identity și persistență

Migrarea 112 creează `provider_artifact_catalog`. Cheia publică este `dda_art_` plus 26 hex din SHA-256(host, kind, UUID/native reference). UUID-ul are prioritate; altfel stabilitatea este `derived`. Native reference are hash pentru lookup și valoare AES-256-GCM pentru operațiile viitoare, dar nu intră în JSON-ul public. Upsert-ul actualizează snapshot-ul și `last_seen_at`, fără hard-delete pe un read parțial.

În WAL mode, o conexiune care pierde upgrade-ul read→write poate primi imediat `SQLITE_BUSY_SNAPSHOT`; catalogul reia tranzacția completă de maximum cinci ori. Alte erori SQLite sunt fail-closed și nu sunt retried.

## Adaptare per provider

### Proxmox

- QEMU `template=1` din cluster resources → `vmTemplate`;
- storage content `iso` → `iso`;
- storage content `vztmpl` → `containerTemplate`;
- `(kind, volid)` dedupe pentru storage shared observat de pe mai multe nodes.

### vSphere/ESXi

- PropertyCollector cere `config.template`; `listVMs()` elimină template-urile;
- template records → `vmTemplate`;
- `SearchDatastoreSubFolders_Task` cu `IsoImageFileQuery` → `iso`;
- un datastore inaccesibil produce skip sanitizat, nu scurge path/credential în API.

### Xen Orchestra și XAPI

- XO folosește `/rest/v0/vm-templates`; numai 404 activează fallback la colecția `vms`;
- XAPI face un singur `VM.get_all_records` și filtrează `is_a_template`, excluzând control domains/snapshots;
- raw xl/xm nu are un catalog persistent portabil și declară `inventory.image=unsupported`.

## Security și limits

- host access `view`, fără mutation și fără audit write;
- safe provider/kind/ID regex;
- 64 KiB maxim per artifact, 2 MiB per envelope, 500 rezultate publice, 5.000 raw rows maxim;
- search maxim 120 caractere;
- provider failures devin erori generice; detaliile sensibile nu ajung în response.

## Extensibilitate V1.6

Tabela păstrează referința encrypted necesară clone/create, dar V1.6 trebuie să o rezolve numai sub host scope, să reprobeze artefactul live și să execute preflight/idempotency/lock/reconcile prin operation engine. Prezența în catalog nu implică automat drept de provisioning.
