# V0.2 Feature spec — identitate și modele comune de resurse

## Problemă

Proxmox, vSphere și Xen returnează forme diferite pentru aceeași resursă. UI-ul și operațiile viitoare nu pot folosi un VM, host, cluster, storage, network sau task fără branching vendor-specific. Referințele native pot fi opace, instabile sau nepotrivite pentru expunere publică.

## Outcome

Provider SDK expune inventar în schema comună `1.0`, cu ID canonic Docker Dash, provider UUID păstrat când există și native reference criptată intern. Prima versiune normalizează resursele deja disponibile din Proxmox, vSphere și Xen.

## API

```http
GET /api/providers/:hostId/resources/:kind
GET /api/providers/:hostId/resources/:kind?limit=200
```

`kind` acceptă `virtual-machines`, `hosts`, `clusters`, `storages`, `networks`, `tasks`.

Envelope:

```json
{
  "schemaVersion": "1.0",
  "kind": "virtualMachine",
  "provider": { "type": "xen", "endpointId": 7 },
  "observedAt": "2026-07-26T12:00:00.000Z",
  "count": 2,
  "totalObserved": 2,
  "truncated": false,
  "items": []
}
```

## Model comun de bază

- `schemaVersion`, `kind`, `id`, `displayName`, `observedAt`;
- `provider.type`, `provider.endpointId`;
- `identity.uuid`, `identity.stability` (`stable`, `derived`, `transient`);
- `labels` și `relationships` bounded;
- `spec` — configurație/capacitate observată;
- `status` — state, health și valori runtime;
- `actions` — allowed operations per-resource;
- `extensions` — allowlist safe pentru date vendor-specific.

Native refs, MoRefs, XAPI OpaqueRefs, credentials și raw responses nu sunt expuse.

## Modele pe kind

| Kind | Câmpuri comune principale |
|---|---|
| `virtualMachine` | CPU, memory, guest OS/IP, power state, host/cluster relationship, actions |
| `host` | address, CPU, memory total/free, version/product, enabled/maintenance/health |
| `cluster` | master/coordinator, HA enabled, default storage, health |
| `storage` | type, capacity/used/free, shared/attached, health |
| `network` | bridge, VLAN, MTU, CIDR, managed, health |
| `task` | state, progress, start/end, result summary, safe error summary |

## Persistența identității

Migrarea 106 adaugă `provider_resource_identities`:

- canonical ID și host/kind/provider;
- provider UUID opțional;
- hash al native ref pentru lookup;
- native ref criptată AES-256-GCM;
- stability, first/last seen;
- uniqueness per endpoint/kind/UUID sau native hash;
- cascade la ștergerea hostului.

ID-ul canonic este determinist pentru endpoint + kind + stable identity. Dacă provider UUID rămâne același și native ref se schimbă, canonical ID rămâne neschimbat.

## RBAC și siguranță

- aceeași regulă host-scoped `view` ca endpoint-ul capabilities;
- endpoint-ul refuză kind-uri necunoscute și capability `unsupported/unknown`;
- maximum 500 itemi per răspuns, implicit 200;
- labels/extensions/reasons și response data sunt bounded;
- native reference poate fi rezolvată numai server-side pentru host/kind-ul așteptat;
- inventarul nu introduce mutation pe provider; singura scriere este mapping-ul local criptat.

## Acceptance criteria

1. toate cele șase kind-uri au schema comună validată;
2. aceleași date produc același canonical ID;
3. native ref nu apare în JSON și este criptată în DB;
4. UUID stabil supraviețuiește schimbării native ref;
5. resursele tranziente sunt marcate explicit;
6. Proxmox normalizează VM/host/storage;
7. vSphere normalizează VM/host/storage/network;
8. Xen normalizează VM/host/cluster/storage/network/task în funcție de variantă;
9. capability gating și host access sunt testate;
10. limit/truncation și response bounds sunt testate;
11. legacy provider endpoints nu își schimbă forma.
