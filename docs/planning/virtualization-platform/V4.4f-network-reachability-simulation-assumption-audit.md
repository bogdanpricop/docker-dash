# V4.4f — Network reachability simulation assumption audit

| Assumption | Evidence / decision | Result |
|---|---|---|
| A route and allow policy prove end-to-end connectivity | Link state, endpoint identity and the data plane can still differ | Rejected; the verdict is labeled a prediction |
| Historical allowed flow proves the tuple works now | Flow evidence may be stale or describe a previous policy/version | Rejected; flow is corroboration only |
| Missing evidence can be treated as deny | Missing and explicit negative evidence have different operational meaning | Rejected; incomplete evidence is `unknown` |
| Missing evidence can be treated as allow | This would create a false assurance boundary | Rejected; pass requires fresh positive evidence |
| Resolving a hostname during assessment is harmless | It starts traffic from the management plane and may use an unintended resolver | Rejected; only retained normalized DNS evidence is read |
| Provider trace results have a universal meaning | Providers expose different trace, policy and freshness semantics | Rejected; adapters normalize an explicit timestamped allow/deny signal |
| An arbitrary source may be emulated safely | Source spoofing and runner placement can bypass the intended trust boundary | Rejected; active probes require verified source ownership |
| Any destination supplied by an admin is safe to probe | It can become an SSRF/scanning surface or violate tenant policy | Rejected; active execution requires destination policy and egress controls |
| A shell-based ping/nc wrapper is sufficient | It permits command injection and uncontrolled protocols/options | Rejected; arbitrary shell remains prohibited |
| Active probes are necessary for the first useful slice | Existing normalized route, policy, attachment, DNS and flow evidence support a bounded prediction | Rejected; V4.4f ships simulation-only first |
