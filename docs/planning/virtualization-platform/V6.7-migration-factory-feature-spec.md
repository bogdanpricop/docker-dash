# V6.7 — Guarded migration factory

**Release:** v8.74.0

**Backlog:** B416–B425

**Date:** 2026-07-30

## Outcome

This batch adds a provider-neutral migration factory for assessment, conversion
contracts, target mapping, isolated validation, waves and evidence. The control
plane deliberately has no conversion/cutover/rollback executor; real provider
work must be performed by a separately approved adapter that returns evidence.

## Assessment, conversion and target mapping

- B416 normalizes bounded source VM inventory and dependency edges, derives
  passthrough/missing-format blockers and ranks target candidates from capacity,
  compatibility, network and storage scores.
- B417 invokes a real fixed Node subprocess with an empty environment, 32 MiB
  heap, two-second timeout and bounded output. It receives only formats and
  SHA-256 input/expected-output checksums and selects a qemu-img or virt-v2v
  contract; no path is exposed and no binary, disk I/O or network call occurs.
- B418 records VLAN, CIDR, security-profile and preserve/reallocate IP mapping.
  Preserving an address across unequal CIDRs blocks the plan.
- B419 aggregates per-datastore byte reservations and retains target policy,
  tier and thin/thick intent. Insufficient capacity blocks the mapping.

## Validation and orchestration plans

- B420 accepts only isolated/no-uplink/sandbox clone evidence and requires all
  supplied checks plus ready network/storage mappings. Source cutover stays zero.
- B421 performs a bounded topological sort of workload dependencies into
  concurrency-limited waves with application, window and downtime context;
  missing dependencies or cycles block readiness.
- B422 requires ready assessment/waves, a validated clone on the exact target,
  SHA-256 approval evidence and exact `CUTOVER <assessment> <target>` text. The
  fixed final-sync/shutdown/network/boot/validation sequence has no executor.
- B423 checks source network/power restoration and target cleanup support before
  producing fixed rollback steps; it also has no executor.
- B424 binds assessment, conversion, cutover and rollback hashes with bounded
  timing/test/approval objects. Raw artifacts are not copied into the report.
- B425 normalizes xm/xl/Xend inventory, identifies legacy capture and
  passthrough blockers and supplies an XAPI/XCP-ng guided migration checklist.

## Persistence and authorization

Migration 148 adds ten migration-factory tables and the permissions
`migration_factory.manage` and `migration_cutover.manage`. Administrator-only
routes audit every accepted write. The Migration Factory governance tab exposes
capability, safety, assessment and artifact-ledger state with zero implicit
provider mutations.
