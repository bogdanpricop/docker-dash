# V3.4 — Recovery restore assumption audit

| Assumption | Evidence | Risk if wrong | Decision |
|---|---|---|---|
| PVE QEMU restore is the create endpoint with `archive` | current official `qemu-server` API schema and PVE API viewer | wrong mutation or overwrite | implement only this documented path |
| PVE LXC restore is the create endpoint with `ostemplate` and `restore=1` | current official `pve-container` API schema | template creation instead of restore | require both fields and guest-type evidence |
| `force` can overwrite existing guests | official PVE API schema | production data loss | never expose it; always submit false and revalidate absence |
| `start`/`live-restore` can run the workload | official PVE API schema | network/identity collision | always false in V3.4 |
| `unique` randomizes restored network identities | official PVE API schema | duplicate MACs | always true and still keep guest stopped |
| failed PVE restore can leave disks/config | official `qemu-server` failure path | unsafe automated deletion/retry | no replay and no automatic cleanup |
| a listed archive is still restorable | inventory is necessary but not a dry-run | task may fail after submit | state the limitation; native task and post-state are authoritative |
| verified metadata proves full boot/application recovery | PBS/XO separate integrity and health-check semantics | false recovery confidence | V3.4 does not claim boot/app verification; V3.5 owns drills |
| XO product restore means current REST adapter can restore | restore mutation is in XO JSON-RPC source, not discovered current REST routes | invented/unstable transport | XO mutation remains unsupported |
| file/disk restore can reuse VM restore semantics | upstream workflows have different streaming/attachment boundaries | data disclosure or target corruption | explicit separate unsupported capabilities |
| target free bytes and point size are always known | providers can omit both | false capacity confidence | block only proven insufficiency; warn on unknown and revalidate storage activity |
| cancellation removes a partial restore | PVE stop only controls the task | orphaned partial VM/disks | report manual inspection; never auto-delete |

## Promotion assumptions to prove on a real endpoint

1. PVE token has `VM.Allocate`, source backup read, destination allocation, and task read/stop permissions without broader rights.
2. Shared and node-local repository identity translation matches the installed PVE version.
3. QEMU and LXC restores return UPIDs and remain stopped with unique MACs.
4. A stopped/cancelled task leaves evidence that can be inspected without Docker Dash cleanup.
5. The same idempotency key and crash-recovery checkpoints cannot produce a second restore.
6. The selected storage content type and free capacity observations match the task target.
