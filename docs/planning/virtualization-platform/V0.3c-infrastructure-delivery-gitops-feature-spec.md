# V0.3c — Infrastructure delivery and GitOps safeguards

**Release:** v8.56.0
**Backlog:** B236–B245
**Date:** 2026-07-29

## Outcome

V0.3c extends the V0.3b infrastructure-intent layer into guarded delivery and
IaC interoperability. It reuses the existing Fleet GitOps planner/applicator,
durable provider-operation engine and procedure runner. It does not add a
parallel generic executor, run Terraform, merge pull requests or fetch secrets
into exported inventory.

## Data model and permissions

Migration 130 adds six additive tables: resource manifests, reconcile
controllers/runs, external plan evidence and webhook trigger/delivery evidence.
Webhook secrets use the existing AES-256-GCM installation key; tokens are stored
only as SHA-256. New permissions `infrastructure_gitops.manage` and
`infrastructure_webhook.manage` are granted to site-admin. The first release
remains route-level administrator-only.

## Reconcile state machine

Manual reconcile moves through `planned → approved → apply_authorized/applied`.
Approval recomputes the complete plan from fresh live state and resource
versions. Mutation-bearing evidence requires existing allowlisted durable
operation IDs on the manifest host; Docker Dash does not create a generic
provider request from manifest paths.

A continuous controller is opt-in and scoped. A scheduled tick compares its
latest stored observation. An identical pending plan is reused; changed state
under a pending plan becomes `conflict` and pauses. Blocked ownership/deletion
actions also pause. Resume is always explicit.

## Webhook security

The endpoint token and HMAC secret are shown once. The secret is encrypted at
rest and never included in list/overview responses. Signature input is
`timestamp.nonce.event.raw-body`. Timestamp skew is bounded, the event must be
allowlisted and `(trigger, nonce_hash)` is transactionally unique before the
configured procedure can start. The route has a dedicated rate limit and a
narrow CSRF exemption because it authenticates by HMAC rather than cookies.
