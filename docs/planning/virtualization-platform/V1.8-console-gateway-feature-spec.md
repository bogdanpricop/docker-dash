# V1.8 Feature spec — protected VM console gateway

**Status:** implemented and under release validation; default-off

**Backlog mapping:** B048–B050

## Outcome

An authorized operator can preflight and open a running VM's graphical or serial console from the common VM detail page. A dedicated same-origin gateway brokers the provider connection, isolates credentials, audits the complete session lifecycle and supports an immediate global, endpoint or VM emergency lock.

## Scope

- Proxmox VE RFB through `vncproxy` and `vncwebsocket`;
- vSphere WebMKS ticket transport with standard RFB/noVNC browser rendering;
- Xen Orchestra console proxy;
- direct XenServer/XCP-ng XAPI RFB or VT100 console;
- raw Xen `xl`/`xm` serial console through pinned SSH;
- one-time user-bound launch tokens, active-session bounds and maximum duration;
- default-off feature flag and environment/database emergency controls.

Native SPICE handoff, RDP, VMConnect, clipboard/file transfer, recording and unattended console automation are not part of this slice.

## API and UX

- `POST /api/providers/:hostId/virtual-machines/:resourceId/console/preflight` returns only capability, state, access and permission blockers;
- `POST /api/providers/:hostId/virtual-machines/:resourceId/console` issues a 45-second single-use launch token and same-origin fragment URL;
- `/vm-console.html#<token>` removes the fragment immediately and upgrades `/ws/provider-console` using `binary` and `dd-console.<token>` subprotocols;
- `GET /api/provider-console/access` reports locks and active sessions to administrators;
- `PUT /api/provider-console/access/global`, `/hosts/:hostId` and `/hosts/:hostId/virtual-machines/:resourceId` control emergency locks.

## Acceptance

- no raw launch token, provider credential, ticket or VNC password is persisted or returned after launch;
- tokens are single-use, expiring, user-bound and consumed atomically;
- current session, same origin, role and host permission are rechecked at WebSocket upgrade;
- unsupported provider/protocol/state combinations fail closed in preflight;
- RFB authentication happens server-side and the browser receives only an already-authorized stream;
- active-session limits and maximum duration prevent unbounded resource use;
- emergency locks terminate matching live sessions across cluster nodes;
- issue, open, failure, denial and close transitions are audited without secrets;
- the self-hosted noVNC artifact is reproducible from the pinned dependency.
