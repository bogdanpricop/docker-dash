# V4.4g — Network MTU mismatch detector

**Backlog:** B120
**Status:** local implementation and vSphere/Xen segment collector complete; end-to-end evidence/live capture/browser pending
**Scope:** passive analysis of normalized path evidence

## Outcome

Administrators can submit bounded, normalized path observations for workload,
overlay, storage and live-migration traffic. The detector calculates the MTU
required at every ordered segment, including cumulative encapsulation overhead,
and persists an immutable assessment with pass/fail/unknown findings.

## Evidence contract

- A path declares its purpose, endpoints, desired payload MTU and whether
  don't-fragment semantics are required.
- Ordered segments declare the provider-visible MTU and the encapsulation bytes
  added before the segment. Overhead is cumulative, so nested tunnels remain
  explicit instead of relying on a provider-specific constant.
- A known segment below its calculated requirement is `fail` and identifies the
  bottleneck and deficit.
- Missing MTU, incomplete coverage, expired evidence or unknown required-DF
  state is `unknown`; it never becomes pass.
- A required DF policy reported as cleared is `fail`. DF state is imported
  evidence only and is not tested by this feature.
- A pass means the supplied configuration evidence has sufficient headroom. It
  does not prove packet delivery, routing, firewall behavior or application
  reachability.

## Persistence and bounds

- Assessments are immutable and SHA-256 deduplicated over canonical input and
  calculated results.
- Inputs cap paths, segments per path, text sizes and encoded assessment size.
- Exact schemas reject arbitrary and secret-shaped fields.
- Source timestamps, expiry, coverage and evidence references remain visible in
  the result and UI.

## API and UI

- Admin-only audited assessment endpoint under Network Advanced.
- Network Advanced exposes recent assessments, state/purpose totals, bottleneck
  segment, MTU deficit, DF state and immutable evidence hash.
- The first UI action accepts normalized JSON so provider adapters can be added
  without changing the analysis contract.
- Provider Network Posture can now persist vSphere/Xen virtual-network and
  vSphere standard-vSwitch MTU as provider-native segment evidence. Coverage is
  deliberately incomplete, so a segment-only observation cannot become an
  end-to-end `pass`.

## Safety

- No ping, trace, packet-size probe, socket, DNS lookup or guest command.
- No provider/network mutation, remediation, MTU change or arbitrary shell;
  the explicit capture action performs bounded inventory reads only.
- B119 active reachability/probe execution remains a separate feature and
  requires an allowlisted runner decision.

## Acceptance evidence

- plain, VXLAN and nested-overlay calculations;
- storage/live-migration bottleneck detection;
- incomplete, expired and missing-MTU evidence remains unknown;
- required DF pass/fail/unknown behavior;
- deterministic dedupe, strict inputs and size bounds;
- API audit, UI contract, focused tests, lint and registry reconciliation.
