## Outcome

This increment adds one endpoint-scoped control plane for:

- local-TOTP step-up and four-eyes, time-bound JIT grants;
- four-eyes break-glass requests, one-time activation, closure and independent
  review;
- implicit remote-session metadata recording and explicit screen-recording
  consent/policy metadata;
- public/internal/confidential/restricted resource classification with a
  deterministic policy projection;
- installation-signed JSON and PDF compliance evidence;
- organization-authored CIS, NIST, ISO 27001, SOC 2 and DORA references without
  duplicating their evidence subject;
- a bounded ransomware-recovery score based on immutability, isolation,
  restore testing and credential separation;
- the existing permission catalog, custom roles and organization/site/provider/
  cluster/project/resource scope hierarchy.

B176–B178 were already `Done`. They are part of this exact ten-feature batch
because the new controls exercise those shipped foundations with ten explicit
permissions, delegated-role visibility and provider-bound hierarchy checks.
They are not claimed as newly implemented features.

## Privileged lifecycle

JIT requesters must already hold `privileged.elevation.request` in the selected
scope (or be a global administrator), have local TOTP enrolled and pass a fresh
six-digit step-up. Five failed step-up attempts for the same user/endpoint in
ten minutes start a cooldown. Codes are never persisted.

Only an independent user with `privileged.elevation.approve` can approve the
request and must type `APPROVE JIT <grant-id>`. The requester claims a random
token exactly once; SQLite stores only SHA-256. Validation binds the token to
user, provider endpoint, permission, active state and expiry. Revocation clears
the stored token hash.

Break-glass follows the same four-eyes boundary and requires a ticket,
notification references, reason and 5–60 minute TTL. Screen policy additionally
requires explicit consent and a bounded policy reference. Approval and
activation have separate typed confirmations. Activation returns one token,
which is bound to requester, scope, endpoint and expiry. Closing removes its
hash; a different user with review permission records the final outcome.

The temporary identity is an authorization envelope such as
`break-glass:<request-id>`. It is not a user row, password or standalone login.
Notification references are retained for an external dispatcher, but this
release truthfully returns `notificationsDispatched:false`.

## Session recording boundary

Every new console session records metadata policy and state. Metadata mode is
implicit and stores timestamps, protocol, endpoint/resource identifiers and
close state already needed by the broker. Screen mode requires explicit
consent and a policy reference and records `screen_requested` only.

No screen frames, audio, clipboard content, keystrokes or provider credentials
are accepted or stored. `screen_active` remains reserved for a future legal and
operationally approved media adapter.

## Classification and compliance evidence

Classification is endpoint-scoped and only accepts canonical resources. Its
server-owned policy projection is:

| Classification | Backup | Evidence export | Telemetry |
|---|---|---|---|
| public | allowed | full | standard |
| internal | allowed | metadata | standard |
| confidential | encrypted required | redacted | minimized |
| restricted | immutable + encrypted required | hashes only | disabled |

Exports select the highest classification present on the endpoint. Confidential
bundles omit advisory/CVE and resource identifiers where required. Restricted
bundles contain hashes, counts and minimal state; remote-session rows are
reduced to a count. The bundle includes findings, classifications, posture,
privileged lifecycle evidence, control mappings and bounded audit links.

Because a bundle is endpoint-wide, export is accepted only for organization or
provider scopes. Remote-session rows additionally require
`privileged.session_recording.read`; otherwise they are withheld explicitly.

JSON and PDF are SHA-256 hashed and signed using HMAC-SHA256 with the
installation encryption key. Only hash, signature and summary are persisted.
The raw bundle, raw configuration, secrets and session screen content are not
stored. The signature proves integrity to a verifier holding the same
installation key; it is not a public attestation.

Framework mappings accept organization-authored references for CIS, NIST,
ISO27001, SOC2 and DORA. A unique evidence subject remains singular and can
carry multiple mapping references. Docker Dash supplies no normative control
text and makes no certification verdict.

## Ransomware-recovery posture

Each observation contains four closed-schema factors: immutability, isolation,
restore tests and credential separation. Every applicable verified factor has
equal weight. Unknown factors reduce confidence; `not_applicable` factors leave
the denominator. Inputs retain only bounded symbolic evidence references,
timestamps and an immutable evidence hash. No restore or destructive recovery
operation is started.

Global administrators retain their existing explicit bypass. Other users are
evaluated through the existing custom-role bindings for the requested scope.
Approval visibility is distinct from session-metadata visibility. Scope
ancestry is cycle-checked, and provider metadata or `provider-host:<id>` keys
cannot cross endpoint boundaries.

TTL transitions use SQLite time functions rather than lexical timestamp
comparison. Claim and activation updates are conditional so concurrent callers
cannot receive two valid tokens.

## API and audit

The endpoint surface is rooted at
`/api/providers/:hostId/privileged-compliance` and includes overview, JIT,
break-glass, classification, mapping, posture and export routes. Every mutation
requires authentication, host operate access, write mode and a scoped service
permission or current JIT/break-glass token.

Audits include provider/scope, state, evidence hashes and whether any provider
mutation, notification, temporary account, bundle storage or secret storage
occurred. They never receive TOTP values, raw grant tokens, bundle content or
session media.
