## Deployment method and rollback evidence

Each host verified and extracted the same checksummed Git archive, then built
the production Docker target with `APP_VERSION=8.58.0`. The application-only
recreate used the base project directory and environment while the release
compose file selected the immutable image:

```sh
APP_VERSION=8.58.0-1e5e8c8 docker compose \
  --project-directory "$BASE" --env-file "$BASE/.env" \
  -f "$RELEASE/docker-compose.yml" up -d --no-build --no-deps app
```

The first LAN verification contained an operator-side SQL quoting error after
the new container was healthy. The error trap correctly recreated the previous
`8.57.0-8e19e0e` application, which returned healthy with zero restarts. The
verification query was corrected to bind `sqlite_master.type` as a value, and
the same backed-up release was redeployed successfully. No restore was needed;
migration 132 is additive and idempotently remained applied.
