# V4.4m — Network and backup operational qualification

**Release:** v8.86.0
**Exact batch:** B124, B125, B129, B130, B131, B132, B133, B134, B135, B136

## Purpose

All ten implementations were included in v8.80.0, while their registry text
still mixed release inclusion with provider, canary and browser evidence. This
slice records what the deployed local control plane can prove without invoking
an executor or converting absent evidence into success.

## Contract

`GET /api/providers/:hostId/operational-qualification?batch=network-backup`
returns the exact ordered batch above. The original endpoint without `batch`
continues to return the v8.85 foundation batch.

Each item reports required tables and additive columns, bounded provider/global
runtime counts, implementation and qualification releases, outstanding gaps
and a deterministic evidence hash. B129–B136 additionally report policy, plan,
execution, child and integrity-evidence counts plus the distinct policy and
execution release flags.

The Provider Security page loads and renders both qualification batches. Empty
evidence is `not_observed`; it is not a successful backup, validation, provider
canary, public-IP apply or browser smoke.

## Safety boundary

- B124 reads persisted plan evidence and its zero mutation counters; apply is
  still absent pending R8, an approved provider adapter and canary.
- B125 reads immutable validation evidence; no executor is authorized by the
  qualification response.
- B129–B136 read policy/plan/execution evidence without dispatch or reconcile.
  `DD_PROVIDER_BACKUP_POLICIES` and `DD_PROVIDER_BACKUP_EXECUTION` are reported,
  never changed.
- The endpoint starts zero provider mutations, network calls and external
  commands. Browser smoke stays `not_recorded` because no integrated browser
  runtime was exposed during this release session.

## Acceptance

- exact ordered count of ten and explicit batch identity;
- required table/column absence remains `missing`;
- provider-scoped B124/B125 evidence never consumes another endpoint's rows;
- backup counts are scoped through policy ownership to the selected endpoint;
- release flags are deduplicated in the summary and remain default-off unless
  the deployment explicitly enables them;
- stable evidence hash for unchanged state;
- focused service/page tests, registry validation, lint and full regression
  pass before publication.
