# V2.2 — Native VM migration

## Outcome

An operator can submit an eligible live, cold, or storage-assisted VM migration inside one configured provider endpoint. The request becomes a durable `vm.migrate` operation with native-task progress, bounded cancellation, reconciliation after restart, and post-migration placement verification.

## Included

- Proxmox VE QEMU and LXC migration through the native migration task API.
- vCenter/vSphere relocation through `RelocateVM_Task`.
- XenServer/XCP-ng XAPI pool migration through `Async.VM.pool_migrate`.
- Runtime-gated Xen Orchestra execution only when its OpenAPI document exposes a task-backed migration action with a recognized schema.
- Semantic plan hash, five-minute validity window, exact-name confirmation, idempotency key, VM/target/storage locks, audit event, Activity Center hand-off.
- Immediate compatibility revalidation before native submission and location/power-state verification after the task completes.

## Excluded

- Cross-provider, cross-endpoint, and cross-pool `migrate_send` workflows.
- Automatic shutdown/start orchestration for cold migration; the operator must stop the VM first.
- Raw `xl`/`xm` migration, because it has no durable native task contract.
- Unverified Xen Orchestra action names or guessed request bodies.
- Reuse of the legacy URL-to-Proxmox import workflow.

## Acceptance criteria

1. A disabled release flag makes preflight inspectable and submission impossible.
2. A plan is bound to VM, source placement, target, mode, optional storage, capability evidence, and power state.
3. Submission recomputes the plan and rejects stale hashes, missing typed confirmation, invalid identity, active resource conflicts, or policy blocks.
4. Execution revalidates provider placement and compatibility before exactly one native submission.
5. A native task reference is stored before reconciliation; non-idempotent submission is never retried automatically.
6. Reconciliation reports progress and succeeds only after the VM is observed on the selected target.
7. Cancellation is confirmed only when the provider accepts native task cancellation; otherwise the operation remains reconcilable.
8. API and UI expose no native identifiers or credentials.
