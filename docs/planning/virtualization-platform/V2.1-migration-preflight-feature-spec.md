# V2.1 — Migration compatibility and preflight

## Outcome

The common VM detail exposes same-endpoint migration candidates, an explainable live/cold/storage capability matrix, blockers, warnings, capacity headroom, and bounded downtime estimates. This batch is read-only: it never submits, reserves, queues, or executes a migration.

## Scope

- B051: per-VM/per-target capability matrix for live, cold, storage, and cross-cluster migration.
- B052: CPU/software, device, storage, network, host-state, maintenance, capacity, version, and provider checks where evidence exists.
- B053–B055: action readiness only; execution remains V2.2.
- B056: explicitly reports the current endpoint/credential boundary and blocks unsupported cross-cluster assumptions.

## Acceptance

1. Native VM/host references and provider credentials never leave the server.
2. Every check names its source and confidence; unknown never becomes supported.
3. Current, offline, disabled, maintenance, and insufficient-memory targets are excluded or blocked.
4. Provider-specific failures degrade to warnings without hiding the VM detail page.
5. Downtime is a range with methodology and confidence, not a promise.
6. No write route, operation handler, or migration feature flag is introduced.
