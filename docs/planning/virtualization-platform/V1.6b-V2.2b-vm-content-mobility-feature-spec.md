# V1.6b / V2.2b — Governed content and VM mobility

**Release:** v8.76.0

**Backlog:** B041–B044, B047, B049, B053–B061

**Date:** 2026-07-30

## Outcome

This batch completes image/template lifecycle and the advanced planning layer
around the durable VM migration and protected-console engines already deployed.
It does not introduce a competing provider executor.

## Content, leases and guest access

- B041 plans digest-bound replication to capacity/format-validated targets with
  bounded concurrency, byte progress and post-copy verification.
- B042 registers immutable semantic template versions with owner, compatibility,
  notes, deprecation and replacement metadata.
- B043 permits only dev→test→prod adjacent promotion; production requires two
  distinct approval hashes and all checks passing against the immutable digest.
- B044 binds a VM TTL to owner notification, stop/delete intent and extension
  limits. Expiry never silently runs destructive work.
- B047 accepts shutdown/reboot or an immutable script reference+SHA-256 only
  when the official agent is installed, healthy and declares the operation.
- B049 models noVNC/WebMKS/serial proxy and native SPICE handoff with capability
  evidence, single-use token limits, clipboard/file controls and mandatory audit;
  sessions continue through the existing protected gateway.

## Migration controls

- B053–B055 add live/cold/storage state, capability, capacity, preflight,
  downtime and post-validation controls bound to durable `vm.migrate`.
- B056 validates cross-pool network/storage maps and an identity broker boundary
  without storing credentials.
- B057 links assessment/conversion/map/test/cutover/rollback hashes into fixed
  cross-provider export→convert→import→test→cutover phases.
- B058 records throttle, compression, migration network and maintenance window.
- B059 previews weighted fair aging with global and per-tenant concurrency caps.
- B060 allows cancel only when native/provider state supports it. Force-complete
  additionally requires terminal success evidence and verified placement.
- B061 derives compensated rollback steps from the exact failure stage and
  source/network/storage/target-cleanup preconditions.

## Persistence and safety

Migration 150 adds fifteen ledgers and the permissions
`content_lifecycle.manage`, `vm_guest_commands.manage` and
`migration_operations.manage`. Cross-pool/provider, replication, promotion and
rollback records expose no execute/apply endpoint. Same-provider submission,
console sessions and cancellation reuse their established guarded executors.
