# V1.8 Assumption audit — VM console gateway

**Audit date:** 26 July 2026

**Decision:** broker all hypervisor consoles through a dedicated same-origin, server-authenticated gateway

| Assumption | Primary evidence | Decision |
|---|---|---|
| vSphere can issue a one-time WebMKS console endpoint | Broadcom documents [`AcquireTicket`](https://developer.broadcom.com/xapis/virtual-infrastructure-json-api/latest/sdk/vim25/release/VirtualMachine/moId/AcquireTicket/post/) and the [`webmks` ticket type](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.VirtualMachine.TicketType.html) | acquire server-side; accept only `wss:` and never expose the ticket |
| noVNC can use an existing authorized WebSocket | official [noVNC API](https://novnc.com/noVNC/docs/API.html) defines the RFB target as a URL or WebSocket; [library guide](https://novnc.com/noVNC/docs/LIBRARY.html) documents embedding | pass the gateway WebSocket directly to the self-hosted RFB client |
| Xen console protocol/location are discoverable | XenServer's official [console class](https://docs.xenserver.com/en-us/xenserver/developer/xenserver-8/management-api/class-console.html) exposes protocol and location; [API extensions](https://docs.xenserver.com/en-us/xenserver/8/developer/sdk-guide/xs-api-extensions) document HTTPS CONNECT with `session_id` | select RFB then VT100 and keep the session ID server-side |
| Xen Orchestra has a maintained console proxy | official XO server source implements `/api/consoles/:id` and its console proxy in [`index.mjs`](https://github.com/vatesfr/xen-orchestra/blob/master/packages/xo-server/src/index.mjs) and [`proxy-console.mjs`](https://github.com/vatesfr/xen-orchestra/blob/master/packages/xo-server/src/proxy-console.mjs) | require a scoped configured token; do not claim support for password-only XO config |
| Proxmox has a browser VNC ticket/WebSocket sequence | official [Proxmox VE API viewer](https://pve.proxmox.com/pve-docs/api-viewer/) defines `vncproxy` and `vncwebsocket` VM endpoints | create the short ticket on demand and terminate VNC auth in the gateway |
| native SPICE handoff fits credential isolation | Proxmox `.vv` handoff embeds a short-lived password intended for a native client | do not expose native SPICE in this security boundary; use the provider's VNC browser path |
| B162–B164 are part of console delivery | the research backlog defines them as certificate rotation, CVE correlation and exposure-based patch priority | remove them from V1.8; schedule them in a later security-posture batch |

## Version caveats

- VMware RFB extension banners are accepted only through their documented standard-RFB downgrade behavior; unsupported security types fail closed.
- XO paths are based on the maintained official server contract and require a scoped token.
- direct XAPI console availability varies by VM and host; the actual console records decide capability at launch.
- raw Xen provides serial console only and inherits strict SSH host-key validation.
- noVNC is pinned to 1.5.0 because the 1.6.0 npm CommonJS artifact is incompatible with the current single-file IIFE build path; an upgrade requires a separate bundler compatibility check.
