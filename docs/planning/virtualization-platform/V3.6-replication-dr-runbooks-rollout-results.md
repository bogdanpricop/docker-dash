## Rollback behavior exercised

Three harness assertions failed safely before the final promotion:

1. the initial release directory was created read-only before extraction; `tar` failed before build or promotion;
2. the corrected build became healthy, but a verification query used SQLite identifier quoting for a string literal;
3. the next healthy promotion expected the internal capability label `not_implemented`, while the public normalized state is `unsupported`.

The first failure left the V3.5 container untouched. The other two triggered the remote `ERR` trap, restored the V3.5 environment and `docker-dash:8.21.4-926e6d1`, and returned it healthy with zero restarts. The final resume revalidated the immutable backup, release and image, then passed every gate. No protection group, DR run or provider operation was created; every temporary session was cleaned.

Application rollback remains anchored at `docker-dash:8.21.4-926e6d1` with the saved environment and Compose coordinates in the V3.6 backup directory. Migration 121 is additive; the verified database backup is retained for explicit incident recovery and must not be restored automatically over a live database.
