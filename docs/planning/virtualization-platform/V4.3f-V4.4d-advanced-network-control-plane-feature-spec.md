# V4.3f / V4.4d — Advanced network control plane

**Release:** v8.79.0

**Backlog:** B102, B103, B105–B117

## Outcome

This release closes fifteen network lifecycle and security items with ten
persistent ledgers and eleven audited write contracts. Existing provider
network posture/topology/placement/drift views remain authoritative for live
inventory. The guarded platform-firewall engine and signed marketplace
IPAM/DNS plans are referenced as execution boundaries rather than duplicated.

## Persistence and authorization

Migration 152 creates ten tables for NIC, mapping, segment, tenant-network,
address, security-group, distributed-firewall, microsegmentation and flow-log
evidence. Four governance permissions are registered:
`network_attachment.manage`, `network_fabric.manage`,
`network_security.manage` and `network_flow.ingest`. Every write requires an
authenticated administrator, writeable mode and an audit record.

## Safety boundary

- Strict schemas reject unknown or secret-shaped fields; identifiers, hashes,
  arrays, CIDRs, IPs, ports, VLANs, VNIs and timestamps are bounded.
- Missing capability, unknown conflicts, incomplete evidence and lockout risk
  produce `blocked`, never optimistic readiness.
- Flow ingestion accepts normalized fields only, stores no raw packet/event
  payload and performs no probe or network call.
- No new route exposes execute, apply or provider mutation. Changes require an
  established guarded executor or a separately approved adapter.
- Governance exposes all fifteen capabilities and the recent distributed-policy
  and flow ledgers without mutation controls.
