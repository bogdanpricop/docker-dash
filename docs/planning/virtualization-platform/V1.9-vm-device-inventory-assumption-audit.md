# V1.9 — Assumption audit

| Assumption | Decision |
|---|---|
| A provider advertising VM inventory also exposes device detail | False; disk and NIC reads have separate capability keys and section states. |
| A configured device is currently connected | False; configuration and runtime attachment are represented separately. |
| Missing hot-plug evidence means unsupported | False; it is `null`/unknown unless the provider explicitly proves true or false. |
| Storage allocation is equivalent across vendors | False; capacity and allocated bytes are preserved independently and may be absent. |
| Guest IP information is authoritative | False; its source is labeled (guest agent/tools/provider) and may be stale. |
| vSphere virtual devices have stable array order | False; correlation uses device/controller keys and backing identity. |
| Xen Orchestra exposes every relation on every version | False; relation reads are bounded and partial failures become warnings. |
| Raw Xen can provide persistent topology | False; `xl`/`xm` inventory is runtime-only and explicitly incomplete. |
| Read-only inventory authorizes attach/detach | False; all mutations remain feature-gated future work. |
