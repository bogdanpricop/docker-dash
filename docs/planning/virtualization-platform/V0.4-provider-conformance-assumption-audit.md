# V0.4 Assumption audit

| Presupunere | Risc | Decizie / evidence necesar |
|---|---|---|
| Numele providerului implică o versiune compatibilă | fals pozitiv | manifestul declară doar familia API; versiunea devine endpoint-tested numai după run live |
| Un probe reușit înseamnă că toate inventory-urile funcționează | parțial | fiecare inventory declarat se validează separat |
| Fixture-ul dovedește compatibilitate reală | falsă certificare | grade-ul static este contract/fixture, distinct de live endpoint evidence |
| Retry nelimitat ajută disponibilitatea | cascadă și rate-limit | circuit breaker, coadă și concurrency bounded |
| Timeout-ul înseamnă că apelul s-a oprit | rezultat tardiv | runner-ul ignoră completarea tardivă; nicio mutation în live suite |
| Mesajele providerului sunt sigure | secret leakage | sanitizer + leak scan; mesajele brute nu sunt persistate |
| ID-urile sunt stabile | UI/audit incorect | două citiri read-only compară eșantionul disponibil |
| Operatorul poate porni o certificare | trafic necontrolat | doar admin; operatorul citește dacă are host access |
| Scorul este adevăr absolut | decizie greșită | scorecard-ul păstrează starea și evidence, nu doar procentul |
| B442–B444 sunt deja implementate ca mutations | scope creep | V0.4 verifică declarațiile; execuția canary/wave/post-check vine cu batch-urile mutabile |

| VPS-ul poate fi accesat ignorând mismatch-ul SSH | MITM | strict host-key rămâne gate obligatoriu |
