# V2.2 — Assumption audit

| Assumption | Failure risk | Control |
|---|---|---|
| A ready V2.1 result remains valid | placement/capacity changes after review | recompute plan on submit and revalidate immediately before provider call |
| A missing response means submission failed | duplicate non-idempotent migration | never auto-retry; reconcile observed placement and otherwise mark unknown |
| Cold migration may stop a running VM | unexpected outage | cold mode is blocked until the VM is already stopped |
| Every Xen interface has equivalent semantics | irreconcilable raw/XO operations | XAPI only by default; XO schema discovery; raw Xen unsupported |
| Provider task completion proves success | VM may remain on source or be inaccessible | post-task canonical placement and power-state verification |
| Cancellation always stops movement | provider may reject/ignore cancellation | expose confirmed cancellation only from provider evidence |
| Target display name is a stable identifier | wrong-host execution | resolve canonical target identity server-side and lock it |
| Storage names are safe client input | injection/wrong datastore | accept canonical storage ID and resolve native identity server-side |
| Same endpoint implies cross-cluster support | provider-specific incompatibility | same-endpoint scope plus native compatibility gates; cross-cluster remains excluded |
