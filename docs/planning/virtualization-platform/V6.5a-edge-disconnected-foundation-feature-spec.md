# V6.5a — Edge and disconnected operations foundation

**Release:** v8.65.0

**Backlog:** B326–B335

**Date:** 2026-07-29

## Outcome

This batch introduces a fail-closed control surface for sites that are expected
to lose central connectivity. It persists local evidence and signed plans while
keeping provider and agent execution outside the central service.

## Safety contract

- Unknown secret-shaped fields and credential-bearing URLs are rejected rather
  than ignored. Stored payloads are bounded and JSON serializable.
- Offline actions and runbooks use fixed allowlists. HMAC signatures cover the
  complete normalized identity, hashes, prerequisites and expiry.
- An offline intent cannot become agent-ready until its signature and expiry
  pass and every stored prerequisite has fresh `pass` evidence. This state
  transition starts zero provider mutations.
- Heartbeat sequence must strictly increase per registered active agent, making
  replay visible. Expected offline windows suppress false outage state without
  claiming a healthy connection.
- Store-and-forward acknowledgement requires the exact sync plan hash and can
  mark only the immutable event IDs selected by that plan.
- Update, bootstrap and mirror readiness requires caller-supplied external
  signature verification from a site trust root. Docker Dash does not claim to
  perform cryptographic artifact verification or content transfer.
- Agent API authentication/enrollment is intentionally not invented here.
  Heartbeats and event imports remain authenticated admin operations until B350.

## Persistence and authorization

Migration `139_edge_disconnected_foundation.js` adds fifteen site, cache,
intent, heartbeat, event, agent, update and content-manifest tables. It seeds
canary, stable and held rings plus four site-admin permissions. The governance
permission catalog total becomes 61.

## Verification target

The focused suite covers all ten backlog items: migration idempotency, timezone
and unique-host validation, expected disconnect, stale cache, secret rejection,
intent HMAC and complete revalidation, heartbeat replay, compression/dedup/
priority/cursors, hash-bound acknowledgement, runbook allowlists, held and
canary updates, trusted/untrusted manifests and UI/API exposure. Full Jest,
ESLint, syntax and migration checks are required before tag and rollout.
