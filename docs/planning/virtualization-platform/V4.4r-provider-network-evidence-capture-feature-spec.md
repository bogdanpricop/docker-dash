# V4.4r — Provider network evidence capture

**Status:** implemented for v8.91.0; live-provider and browser evidence pending

**Market features:** exactly B015, B045, B090, B096, B104, B118, B119,
B120, B121 and B123

## Outcome

This release continues the first exact ten-feature `Partial` qualification batch
without changing registry status. It adds an explicit, admin-only, read-only
provider capture for the three features where the current provider SDK can add
safe evidence:

| Feature | v8.91.0 delta |
|---|---|
| B118 | Canonical VM/IP inventory becomes an immutable address observation and a rebuilt global dependency snapshot. |
| B120 | Virtual-network MTU and vSphere standard-vSwitch MTU become incomplete segment-only path evidence. |
| B121 | vSphere pNIC membership, link state, speed, duplex and standard-vSwitch teaming order become incomplete Bond/LAG evidence. |

B015, B045, B090, B096, B104, B119 and B123 are revalidated to preserve the
exact batch of ten. Their external prerequisites are unchanged: browser smoke,
disposable-provider mutation canaries, active-probe ownership and provider-native
load-balancer collection are not inferred or started.

## Provider contract

- `POST /api/providers/:hostId/network-evidence/capture` requires an
  administrator with provider `operate` access and writeable application state;
- provider capability refresh, VM/IP inventory, common virtual-network inventory
  and optional native physical-network inventory are bounded reads;
- vSphere physical evidence uses PropertyCollector for at most 64 visible hosts,
  256 pNICs and 256 standard switches per host, then the common envelope bounds
  switches and bonds to 500 each;
- each evidence source is isolated: unavailable or invalid provider evidence is
  returned as `unavailable` without turning missing evidence into health;
- address observation plus dependency snapshot are one SQLite transaction;
- response and audit include the exact feature IDs, evidence hash and zero-work
  safety counters.

## Fail-closed semantics

- zero VM addresses, paths or bonds remain `not_observed`;
- B120 coverage is always incomplete because segment inventory is not an
  end-to-end path and does not prove DF behavior;
- B121 coverage is always incomplete because traffic deltas, LACP partner state,
  link-flap and failover history are not collected;
- unsupported collectors return an explicit unsupported envelope;
- malformed provider fields are filtered or rejected before persistence;
- provider error messages, credentials and native VM identities are not exposed.

## Safety

The capture starts no packet, ping, socket, DNS query, guest command, failover,
link change, provider mutation, remediation, notification or external command.
The UI exposes one explicit action only to administrators and reloads posture
evidence after a successful or partially successful capture.

## Remaining qualification gaps

- browser smoke, because the integrated browser runtime exposed no browser;
- first successful live-provider capture; both configured LAN vSphere endpoints
  were unreachable during pre-release qualification;
- B118 DNS/flow provider adapters;
- B120 end-to-end topology, encapsulation and DF evidence;
- B121 distributed-switch/LACP partner depth, counters and non-vSphere physical
  network collectors;
- the unchanged external prerequisites of the other seven batch features.

No feature is promoted from `Partial` by this release.
