## Rollback behavior exercised

Two pre-promotion harness assertions failed safely. The first used a BusyBox-incompatible regular expression for backup JSON. The second piped the complete API client through an early-closing `grep`, which produced expected `curl 23` under `pipefail`. In both cases the remote `ERR` trap restored the V3.4 environment and image automatically; the container returned healthy with zero restarts. The corrected promotion reused the immutable release/image and the second verified online backup, then passed every gate. Neither failed attempt created a drill run or submitted a provider task.

Application rollback remains anchored at `docker-dash:8.21.4-75c1fe2` with the saved environment and Compose coordinates in the V3.5 backup directory. Migration 120 is additive; the verified database backup is retained for explicit incident recovery and must not be restored over a live database automatically.

## Production promotion gate

Prove all-NIC `link_down=1`, exact target ownership marker, QEMU agent required/optional behavior, LXC boot-only behavior, measured RPO/RTO, shutdown and forced-stop fallback, cleanup-on-success, retained failed targets, cancellation, and ambiguous restart recovery. XO, XAPI, raw Xen, vSphere, and ESXi drill mutation remain fail-closed.
