# V4.4j — NAT/public-IP lifecycle plan assumption audit

| Assumption | Evidence / decision | Result |
|---|---|---|
| A free-looking address can be allocated | Provider quota and concurrent ownership can conflict | Rejected; require quota and conflict evidence |
| Mapping ownership follows the target VM | Addresses can be tenant/shared/service owned | Rejected; bind tenant, owner and ownership token separately |
| Release is safe when a VM disappears | NAT rules, DNS, LB and billing dependencies can remain | Rejected; require zero mappings/dependencies and managed ownership |
| Public cost can use a JavaScript float | Rounding drifts across currencies/providers | Rejected; store integer hourly micros and currency |
| Missing expected version can be ignored | Concurrent mapping changes can redirect traffic | Rejected; map/unmap/release require optimistic version |
| Unknown conflict is equivalent to clear | It may hide an existing allocation or mapping | Rejected; unknown blocks |
| A lifecycle plan may immediately call the provider | Apply needs provider-specific idempotency and rollback | Rejected; no execute/apply route |
| Native refs/credentials are needed in the plan | A future adapter can resolve canonical keys server-side | Rejected; accept canonical keys and evidence only |
