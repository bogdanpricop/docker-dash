# V1.2 Deep spec — VM power

## API

- `POST /api/providers/:hostId/virtual-machines/:id/power/preflight`
- `POST /api/providers/:hostId/virtual-machines/:id/power`
- `POST /api/providers/:hostId/virtual-machines/power/preflight`
- `POST /api/providers/:hostId/virtual-machines/power`

Body preflight: `{ "action": "start|shutdown|reboot|forceShutdown|forceReboot" }`.

Submit single: action, `planHash`, `confirm: true`, iar force cere `confirmName`. Header-ul `Idempotency-Key` are 8–200 ASCII vizibile. Bulk folosește `resourceIds`, `plans` și o cheie de bază de 8–160 caractere; maximum 20, duplicatele sunt eliminate.

## Preflight envelope `1.0`

- canonical host/resource/action și current/expected power state;
- capability evidence și resource allowed action;
- blockers pentru release, capability, state, policy, permission și conflict;
- identity stability blocker pentru resurse raw/tranzitorii care nu pot fi reconciliate sigur după restart;
- warnings pentru clean guest operations și stale tools;
- confirmation mode;
- `planHash` SHA-256 peste câmpurile semantice, fără timestamp;
- `validUntil` informativ; submit recalculează întotdeauna planul.

## Handler `vm.power`

1. rezolvă ID-ul canonic în identity store;
2. recitește VM-ul nativ și verifică state-ul;
3. emite exact un apel mutation;
4. leagă task-ul nativ encrypted, dacă există;
5. poll/reconcile task-ul fără retransmiterea mutation-ului;
6. recitește VM-ul și verifică post-condition;
7. după timeout de verificare returnează `unknown`.

## Provider mapping

| Common | Proxmox | vSphere | Xen |
|---|---|---|---|
| start | status/start | PowerOnVM_Task | VM.start |
| shutdown | status/shutdown | ShutdownGuest | clean_shutdown |
| reboot | status/reboot | RebootGuest | clean_reboot |
| forceShutdown | status/stop | PowerOffVM_Task | hard_shutdown |
| forceReboot | status/reset | ResetVM_Task | hard_reboot |

Proxmox poll-ează UPID status; vSphere poll-ează `Task.info`; XAPI/XO folosesc task endpoint când action response expune task ID. Operațiile sincronizate intră direct în post-verification.

## Failure model

- fault înainte de submit: `failed`, fără mutation evidence;
- fault/timeout după submit: `reconciling` sau `unknown`;
- provider task error: `failed` cu mesaj sanitizat;
- state post-condition absent după fereastra de verificare: `unknown`;
- worker restart: `recoverExpired()` rulează numai reconcile;
- cancellation neconfirmată de provider: `unknown` și lock păstrat.
