# V4.4n — Recovery-depth operational qualification

**Release:** v8.87.0
**Exact batch:** B137, B138, B139, B140, B141, B142, B143, B144, B145, B146

## Purpose

B137–B138 were included in v8.80.0 and B139–B146 in v8.81.0. Their registry
still grouped delivered control-plane work with evidence that requires native
provider adapters, data transfer, fencing, browser smoke or disposable
canaries. This release adds a third read-only qualification batch and preserves
the implementation release of every feature.

## Contract

`GET /api/providers/:hostId/operational-qualification?batch=recovery-depth`
returns the exact ordered IDs above. The existing default and
`batch=network-backup` responses remain available.

The response reports:

- table and additive-column readiness;
- backup encryption policy and strict integrity-evidence counts;
- restore drill policy/run evidence and success counts;
- metadata file catalogs and file-plan evidence;
- instant, differential and cross-site plan counts without execution claims;
- draft replication policy counts and their always-explicit enabled state;
- DR protection-group, member and rehearsal counts;
- distinct release flags and stable SHA-256 evidence.

The batch contains mixed implementation releases. `implementationReleases`
therefore contains v8.80.0 and v8.81.0, while each item retains its own release.

## Safety boundary

- B137 counts local encryption-policy configuration; it never resolves key
  material or claims rotation evidence.
- B138 is `observed` only for persisted item integrity details or strict
  integrity evidence, never from the existence of a generic backup policy.
- B139–B140 read drills and scheduler state without reconciling or dispatching.
- B141 reads metadata only; no backup bytes or download endpoint is exposed.
- B142–B144 read fail-closed plans; no instant, differential or copy task is
  started.
- B145 reads draft policies and reports enabled counts without configuring a
  provider.
- B146 reads protection groups and rehearsals without fencing, cutover or data
  authority reversal.
- No qualification call changes feature flags or starts provider mutations,
  network calls, external commands, browser runs or active probes.

## Acceptance

- exact ordered ten-ID batch and mixed release metadata;
- required tables/columns remain explicit when absent;
- all runtime counts are scoped through the selected provider endpoint;
- missing B138 integrity evidence stays `not_observed`;
- distinct release flags are deduplicated in the summary;
- identical state produces the same evidence hash;
- Provider Security renders all three batches and escapes evidence/gap values;
- focused recovery/qualification/page/registry tests and the full regression
  pass before publication.
