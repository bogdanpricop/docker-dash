# V0.3b — Infrastructure automation foundations

**Release:** v8.55.0
**Backlog:** B226–B235
**Date:** 2026-07-29

## Outcome

V0.3b connects the durable provider-operation core already delivered in V0.3
to an explicit infrastructure-intent layer. Administrators can store secret-free
VM, host and fabric manifests, produce immutable change plans, revalidate them
against fresh evidence and model dependency/compensation workflows. This batch
does not execute a provider action when a plan is accepted or previewed.

## Data model and permissions

Migration 129 adds `infrastructure_manifests`,
`infrastructure_change_plans`, `infrastructure_workflows` and
`infrastructure_plan_jobs`. It also adds
`infrastructure_automation.manage`, granted by default to the site-admin role.
The first release remains route-level administrator-only while the permission
is available for future delegated enforcement.

## Safety model

- Input is bounded before persistence and recursively rejects secret-bearing
  key names.
- Canonical JSON and SHA-256 make manifest revisions and plans deterministic.
- Non-authoritative manifests preserve unmanaged live fields.
- Authoritative removal of image, network or storage paths is explicitly
  blocked until the B236 ownership/deletion gates exist.
- An accepted plan records reviewed intent only. Provider execution can only be
  represented by linking an already allowlisted durable operation on the same
  host.
- Audit entries contain hashes, counts and identifiers, never manifest bodies,
  live state, encrypted requests or native-task ciphertext.

## Operator surface and verification

Governance → Automation & IaC exposes engine evidence, manifest creation,
planning/revalidation, workflow creation, compensation preview and accepted
plan-to-job links. Dedicated tests cover the ten contracts, four-table migration,
permission seed, secret rejection, deduplication, stale evidence, cycle rejection,
compensation ordering and ciphertext non-disclosure.
