# V4.4p — Security lifecycle operational qualification

**Status:** implemented for v8.89.0, provider execution remains fail-closed

**Market features:** B157–B166

## Outcome

The operational-qualification endpoint accepts `batch=security-lifecycle` and
returns exactly B157–B166. It reads local SQLite evidence and release flags
only. It starts no collector, catalog fetch, TLS probe, certificate adapter,
remediation adapter, provider mutation or external command.

B157–B158 retain their v8.82.0 implementation release and B159–B166 retain
v8.83.0. v8.89.0 is an additive qualification release, not evidence that the
remaining native adapters or canaries ran.

## Evidence facets

| Features | Strict runtime evidence |
|---|---|
| B157 | confidential provisioning plans and separately counted allowed plans |
| B158–B161 | exact `hardening`, `virtualHardware`, `transport` or `certificateTrust` facts |
| B162 | host-scoped tracked certificates, ownership and renewal jobs |
| B163 | findings with a non-empty, valid CVE array |
| B164 | persisted findings with server-derived priority/confidence |
| B165 | non-revoked, non-expired finding exceptions |
| B166 | persisted remediation dry-run plans and allowed/blocked counts |

A generic security-evidence row cannot make B158–B161 observed unless its
closed-schema JSON contains the exact requested domain. A finding without a
CVE cannot make B163 observed. An expired/revoked exception cannot make B165
observed. Release flags never substitute for a persisted record.

## Safety and compatibility

- response schema advances additively to `1.4`;
- all earlier batch selectors preserve their exact ordered IDs;
- stable hashes exclude generation time;
- qualification safety counters stay zero for provider mutations, network
  calls and external commands;
- `DD_PROVIDER_SECURITY_ASSURANCE` and
  `DD_PROVIDER_SECURITY_LIFECYCLE` are reported but never changed;
- no plan, secret reference, provider-native reference or certificate material
  is returned by the qualification envelope;
- browser smoke remains `not_recorded` while the integrated runtime is absent.
