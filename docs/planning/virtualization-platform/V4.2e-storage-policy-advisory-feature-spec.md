# V4.2e — Storage policy advisory feature specification

**Status:** shipped in v8.27.0 (2026-07-28)

## Outcome

Storage Posture evaluates live provider inventory against an operator-selected,
transient storage policy: accessibility is required, while minimum free capacity
and shared-storage requirements are optional. The policy is advisory evidence;
it is neither persisted nor applied to a provider.

## Safety contract

1. The endpoint is host-view scoped and requires the existing
   `storage.policy.read` capability.
2. Each target is `compliant`, `noncompliant` or `unknown`. Any negative
   provider observation is noncompliant; an absent accessibility, free-capacity
   or shared-state observation remains unknown and never compliant.
3. Minimum free capacity is an integer from 0 to 64 TiB. The policy reads at
   most 500 normalized storage targets.
4. Policy choices exist only in the request/view. No database record, provider
   configuration, capacity reservation or execution permission is created.
5. This slice performs no storage mutation, test write, provider shell fallback
   or automatic remediation. A disk operation must use its own fresh preflight.

## API

| Method | Path | Access | Effect |
|---|---|---|---|
| `GET` | `/api/providers/:hostId/storage-policy-advisory?minFreeBytes=…&requireShared=true` | host view | bounded live read-only policy evidence |

## Explicit exclusions

- persistent policy management, approval, scheduling, exceptions and remediation;
- storage QoS/multipath discovery, quotas and capacity reservation;
- treating a compliance result as VM placement or disk-operation authorization.
