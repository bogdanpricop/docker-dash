# V1.5 Feature spec — catalog comun de template-uri și imagini

**Status:** implementat, în validare

**Backlog:** B034–B039

**Provideri:** Proxmox VE, VMware vSphere/ESXi, Xen Orchestra, XAPI

## Outcome

Operatorul poate inventaria dintr-o singură pagină artefactele din care vor fi create workload-uri în V1.6: VM templates, ISO images și container templates. Contractul este read-only, versionat și nu expune identificatori nativi.

## Surse oficiale validate

- [Proxmox VE Administration Guide](https://pve.proxmox.com/pve-docs/pve-admin-guide.pdf): storage content include ISO, `vztmpl` și imagini;
- [vSphere VirtualMachine](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.VirtualMachine.html) și [VirtualMachineConfigInfo](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.vm.ConfigInfo.html): template-urile sunt VirtualMachine objects, marcate prin configurație;
- [vSphere HostDatastoreBrowser](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.host.DatastoreBrowser.html): căutarea read-only recursivă a ISO-urilor;
- [XAPI VM class](https://xapi-project.github.io/xen-api/classes/vm.html) și [XAPI overview](https://xapi-project.github.io/xen-api/overview.html): template-urile sunt VM records cu `is_a_template=true`;
- [Xen Orchestra VM Templates](https://docs.xen-orchestra.com/vm-templates) și [REST API](https://docs.xen-orchestra.com/restapi/): colecția versionată `vm-templates`, cu fallback compatibil pentru instalații mai vechi.

## Scope livrat

- capability aditiv `inventory.image`;
- API `GET /api/providers/:hostId/artifacts` cu `kind`, `q`, `limit`;
- kinds publice: `vmTemplate`, `iso`, `containerTemplate`, `diskImage`, `contentLibraryItem`;
- ID opac stabil `dda_art_<hash>` și referință provider AES-256-GCM encrypted;
- provenance bounded: node, storage, pool, library și source;
- specificații comune: OS, architecture, version/format, size, CPU, memory, default;
- search și filtrare în pagina `VM Catalog`;
- separarea template-urilor vSphere de inventarul VM executabil;
- deduplicarea conținutului Proxmox de pe storage shared;
- fallback XO `vm-templates` → `vms?is_a_template` numai pentru răspuns 404.

## Non-goals

- clone/create/import/upload/delete;
- Content Library REST pe vCenter — kind-ul este rezervat, integrarea vine după probe de autentificare vAPI;
- download sau proxy de imagini;
- catalog cross-endpoint într-un singur răspuns; UI păstrează host scope/RBAC.

## Acceptance

1. răspunsul nu conține MoRef, UPID, OpaqueRef, volid sau datastore path native;
2. același artefact păstrează ID-ul după refresh și redenumire când are UUID stabil;
3. raw Xen declară explicit capability unsupported;
4. endpointul cere auth și drept `view` pe host;
5. orice provider error este sanitizat;
6. maxim 500 rezultate și 2 MiB/envelope;
7. migrarea este FK-safe și rollback-ul aplicației nu pierde datele existente.
