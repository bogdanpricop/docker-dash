# V3.9 — Provider security lifecycle

**Status:** shipped in v8.83.0; provider collection and remediation adapters
fail closed

**Market features:** B159–B168

**Release gates:** `DD_PROVIDER_SECURITY_LIFECYCLE=false` and
`DD_PROVIDER_SECURITY_LOW_RISK_REMEDIATION=false`

## Outcome

This increment extends the versioned security-assurance control plane with:

- VM virtual-hardware, protocol, certificate-trust and exposure evidence;
- exact version/build correlation against the existing official advisory
  catalog;
- exposure-aware patch priority and explicit confidence;
- owned, reasoned and expiring finding exceptions;
- hash-bound dry-run remediation plans with steps, downtime, dependencies and
  verified rollback;
- a separately gated low-risk executor contract that requires typed
  confirmation, read-only canary, an injected conformance-tested adapter and
  post-read verification;
- manifest/job/template validation that rejects inline credentials while
  persisting only document/reference hashes and finding paths;
- endpoint-scoped certificate ownership and latest renewal state from the
  existing approval-bound certificate lifecycle workflow.

The release does not add a native provider collector, advisory web fetch,
certificate adapter or production remediation adapter. Missing evidence remains
`unknown`; a successful plan never implies that execution is authorized.

## Evidence domains

`provider_security_evidence` remains the single bounded, closed-schema source.
The new domains are:

| Domain | Evidence |
|---|---|
| Virtual hardware | versioned baseline, firmware, boot order, devices and unsafe legacy settings |
| Transport | protocol, port, TLS version, authentication, certificate state and legacy API flag |
| Certificate trust | chain, SAN, expiry, algorithm posture and renewal owner |
| Exposure | workload criticality, reachability and named protections |

Transport and trust controls are derived from facts rather than accepting a
caller-supplied pass/fail verdict. HTTP, TLS 1.0/1.1, password-only SSH,
expired/untrusted/mismatched certificates and legacy APIs fail explicitly.

## Advisory correlation and priority

The correlator reads `lifecycle_version_inventory` and only catalog rows whose
`update_kind` is `advisory`. Catalog ingestion already requires
`sourceKind=official_vendor`, credential-free HTTPS and a source digest.
Security advisory metadata is closed-schema and includes CVE IDs, optional
CVSS, exact affected versions/builds, fixed version and optional canonical
resources.

No range guessing is allowed. A finding is persisted only when current version
or build exactly matches an affected value. Severity supplies the base score;
known criticality and reachability can raise it to 100. Confidence is high only
when both exposure facts are known. Absent exposure lowers confidence rather
than silently lowering severity.

## Exceptions and remediation

Exceptions require owner, reason, future expiry (maximum 366 days) and at least
one compensating control. Revocation and expiry return the finding to open.

Remediation actions are allowlisted and have server-owned risk classes. Plans
require bounded steps, dependency evidence, dry-run success and a verified
rollback strategy. Active exceptions block planning. Every plan is immutable,
hash-bound to current finding evidence, expires after ten minutes and returns
`executionAuthorized:false`.

Low-risk execution is behind a second default-off flag. It revalidates the plan
hash/evidence, requires typed confirmation, runs a mutation-free canary and
requires an explicitly injected adapter. A provider mutation begins only after
the canary; success requires post-read `verified:true`. Failed verification
invokes rollback and records `rollback_required` if reversal is not proven.
No production adapter is registered by this release.

## Certificate rotation

The security view joins endpoint-scoped tracked certificates to lifecycle
ownership and the latest renewal job. It returns subject, SAN, expiry,
fingerprint, owner, environment and renewal state without PEM material.

Actual rotation continues to use the existing lifecycle assurance contract:
approved maintenance dependency, immutable plan hash, separate infrastructure
approval, durable provider operation, apply/verify phases and rollback on
failure. This release does not weaken or duplicate that path.

## Secret-reference enforcement

The validator accepts JSON objects up to 256 KiB for `manifest`, `job` or
`template`. Secret-shaped fields must be symbolic references using approved
manager URI schemes or a Kubernetes `secretKeyRef`. It also rejects
secret-named environment values, embedded private keys and credential-bearing
URLs.

The submitted document is never stored. SQLite receives only its SHA-256,
hashes of normalized references, validation state and bounded path/code
findings. Invalid documents return HTTP 422.

## Security, RBAC and audit

- viewers with endpoint access may read the dashboard;
- correlation, exception, planning, execution and validation require admin,
  endpoint operate permission and write mode;
- resource IDs are re-scoped to the endpoint server-side;
- API/UI output excludes provider-native IDs, PEM and secret values and UI text
  is escaped;
- audits record evidence/plan/document hashes and actual mutation boundary;
- all collection capabilities remain `adapterNotImplemented` until a
  conformance-tested provider implementation exists.

## Verification

- migration constraints, foreign keys, state/risk ranges and hash lengths;
- closed evidence domains and derived hardware/protocol/trust/exposure states;
- exact match versus range-like non-match and cross-endpoint rejection;
- exception creation/revocation/expiry and plan blocker behavior;
- disabled automation, typed confirmation, canary, apply, verify and rollback;
- inline-secret rejection and proof that raw document/reference values are not
  persisted;
- certificate lifecycle projection without PEM;
- admin/host-scope/API status and audit coverage;
- full Jest, ESLint, i18n, accessibility, registry and whitespace gates before
  release.
