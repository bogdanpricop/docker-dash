# V1.9 — VM device inventory deep spec

## Contract

`registry.vmHardwareForHost(host, resource)` resolves the encrypted host-scoped native VM identity, calls the registered provider adapter through the existing resilience boundary, then normalizes the result with `vm-hardware.js`.

The envelope contains:

- `schemaVersion`, provider endpoint, VM canonical ID, and `observedAt`;
- aggregate disk capacity/allocation and connected-device counts;
- bounded `disks` and `nics` arrays;
- section-specific warnings and capability evidence.

Device IDs are deterministic hashes of endpoint, VM canonical ID, device kind, and native device reference. Native references are input-only and never serialized.

## Provider reads

- Proxmox: QEMU/LXC config endpoints; QEMU guest-agent NIC addresses are optional and failure-tolerant.
- vSphere/ESXi: `RetrievePropertiesEx` for `config.hardware.device` and `guest.net`; virtual controller, backing, connectable, and guest-network records are correlated in memory.
- Xen Orchestra: VM `$VBDs`/`$VIFs`, then scoped VBD/VDI/VIF/network reads through REST v0.
- XAPI: VM, VBD, VDI, SR, VIF, network, and optional guest-metrics records; `allowed_operations` drives conservative per-device evidence.
- Standalone Xen: allowlisted `xl`/`xm block-list` and `network-list` reads over the already pinned SSH channel. Runtime-only topology is labeled incomplete.

## Safety boundaries

- No mutation endpoint or operation handler is introduced.
- Native refs and credentials never cross the common contract.
- Provider text is length-bounded and secret-redacted.
- Maximums: 128 disks, 64 NICs, 32 addresses per NIC, 512 KiB envelope.
- Partial provider data remains usable; unknown is preserved instead of inferred.
