# V3.3b — Assumption audit pentru R5a / B129–B138

## Ipoteze acceptate

| Ipoteză | Decizie |
|---|---|
| Un snapshot poate satisface B129 | Respins. Recovery point-ul trebuie să provină din inventory de backup. |
| `full` și `incremental` au aceeași traducere pe orice repository | Respins. Adaptorul trebuie să dovedească semantica. |
| Un selector dinamic poate folosi native refs | Respins. Numai identități canonice și metadata publică normalizată. |
| Excluderile pot fi ignorate dacă providerul nu le suportă | Respins. Execuția este blocată. |
| Application consistency poate cădea silențios la crash | Respins. Fallback-ul este explicit și trebuie dovedit. |
| Concurența per-policy este suficientă | Respins. Repository/host/provider/global pot fi bottleneck comun. |
| Un job provider `OK` dovedește integritatea | Respins. Job + recovery point + metodele cerute sunt dovezi separate. |
| Capabilitatea PBS implică un forced-full | Respins. PBS controlează chunk reuse; forced-full nu este afirmat. |
| vSphere are un endpoint simplu de backup VM | Respins. VADP/VDDK este o suprafață pentru aplicații/data movers. |
| XO REST are aceeași suprafață pe toate versiunile | Respins. Route/action discovery din OpenAPI este obligatoriu. |

## Riscuri rămase

- Nu există încă un canary real R5a în acest working tree.
- XO job execution și vSphere data mover nu sunt implementate; rămân
  capability-gated și nu sunt prezentate drept suport.
- Proxmox storage content poate raporta capabilitatea PBS fără evidence granulară
  checksum/chain pentru fiecare punct; metodele respective rămân `unknown`.
- Excluderile disk/path și hook references sunt modelate și validate, dar
  executorul Proxmox le refuză până există traducere provider-native sigură.
- GFS produce candidates/protection evidence, nu prune/delete.

## Promovare

R5a poate fi promovat din `Partial` numai după:

1. canary Proxmox/PBS pe workload disposable;
2. cel puțin încă un adaptor task-aware cu recovery-point read-back;
3. browser smoke pentru authoring/preflight/execute/integrity evidence;
4. verificarea recovery din `unknown` și a limitelor concurente sub restart;
5. rollout cu feature flag implicit dezactivat.
