# V4.2c — Shared virtual-disk topology assumption audit

| Assumption | Counterexample | Contract decision |
|---|---|---|
| a repeated backing path is safe shared storage | an accidental duplicate attachment can corrupt data | report it as review unless every attachment is explicitly shared |
| a provider's backing reference is safe to expose | VMDK/VDI/volume values can reveal storage layout | return only an opaque host-scoped backing ID |
| selected VM inventory is complete | endpoint limits and provider reads can be truncated or fail | return explicit coverage and partial-evidence state |
| every platform has equivalent shared semantics | vSphere, Proxmox and Xen use different configuration fields | use normalized provider declaration only; do not infer portability |
| seeing two consumers validates the workload | clustered guest/application coordination is outside VM metadata | exclude validation and remediation from this release |

## Audit probes

1. Prove native backing and datastore values cannot appear in the topology response.
2. Prove two attachments are confirmed only when both declare `shared=true`.
3. Prove a missing/false shared declaration remains review evidence.
4. Prove unsupported capability, unreachable provider and unreadable VM inventory fail closed or mark coverage partial.
5. Prove the VM cap and bounded concurrency remain in force.
