# V1.3 Assumption audit — Common VM snapshots

| Ipoteză | Risc | Control |
|---|---|---|
| snapshot este backup | VM și snapshot pierdute cu același storage | guardrail `isBackup=false` în API și UI |
| numele snapshot este identitate | duplicatele sunt permise pe unele platforme | ID canonic din native ref; create refuză duplicate în contractul comun |
| native ref poate fi trimis clientului | disclosure și cross-resource confusion | mapping encrypted server-side, ownership host+VM |
| quiesce poate face fallback | operatorul crede că are application consistency | lipsa evidence blochează, fără downgrade silențios |
| snapshot task success implică inventar actualizat instant | eventual consistency | poll task, apoi bounded inventory verification |
| create poate fi retrimis după timeout | snapshot duplicat | handler non-idempotent și reconciliation-only |
| delete părinte este sigur | poate elimina/consolida subtree | child guard și `removeChildren=false` |
| revert păstrează starea curentă | datele curente se pierd | typed VM name și avertisment destructive |
| toate PVE storages acceptă snapshot | backend/format pot refuza | capability conditional și provider fault safe |
| toate VM-urile vSphere acceptă snapshot | FT/device/state restrictions | live provider task/preflight evidence și bounded failure |
| Xen snapshot este simultan pe toate disk-urile | XAPI snapshot-ează VDI-urile secvențial | consistență declarată explicit din provider evidence |
| raw Xen UUID/domid este suficient | fără snapshot/task model portabil | raw rămâne unsupported |
| metadata integrity este backup integrity | false assurance | states separate; B138 content verification rămâne V3.3 |
