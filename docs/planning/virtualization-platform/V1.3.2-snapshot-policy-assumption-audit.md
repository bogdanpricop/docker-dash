# V1.3.2 Assumption audit — Snapshot policy

| Ipoteză | Risc | Control |
|---|---|---|
| cron este workflow durabil | tick pierdut sau dublat la restart/HA | SQLite slot uniqueness + persistent run state |
| toate snapshot-urile VM aparțin policy | ștergere snapshot manual/backup tool | prefix ownership exact; manual snapshots excluse |
| count retention poate șterge orice părinte | chain corruption/consolidation neașteptată | leaf-only + child guard revalidat de handler |
| timestamp lipsă poate fi tratat ca vechi | ștergere nedeterministă | timestamp-less este protejat |
| policy poate porni create și toate delete simultan | lock conflict și plan stale | un singur child operation; continuare după terminal success |
| child task success înseamnă policy success | eventual consistency | fiecare child folosește V1.3.1 post-inventory verification |
| dry-run enabled poate muta | surpriză operațională | mod separat; dry-run nu apelează operation engine create |
| feature flag off poate fi ignorat de un run existent | mutații după emergency disable | reconcilierea observă child existent, dar nu submit următorul child |
| retenția snapshot este backup retention | false assurance | `isBackup=false` în plan/API/UI și docs separate |
| provider-native VMSS este portabil | semantică/licențiere diferită între versiuni | scheduler comun peste durable provider operations |
| delete poate fi anulat sigur | Broadcom avertizează asupra consolidării | handler nu confirmă cancel pentru vSphere/Xen; no replay |
