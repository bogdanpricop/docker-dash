# V2.3 — Assumption audit

| Assumption | Failure if false | Control |
|---|---|---|
| V2.3 backlog range B066–B070 describes maintenance | HA/affinity scope leaks into this batch | named outcome is authoritative; implement B062–B065 and document mapping defect |
| a read preflight reserves capacity | two planners overcommit the same target | UI says estimates only; child preflight revalidates; active source reservations are blockers |
| every VM placement is present in the common resource relation | Proxmox/vSphere/XAPI rows use different placement fields | resolve source through provider migration compatibility, never by display name alone |
| a successful child task proves the host is empty | DRS/external actor can move or add VMs | refresh complete inventory and compare source placement before terminal state |
| vSphere maintenance evacuates VMs itself | task can wait forever or DRS can race the plan | controlled child migration; bounded task; live state post-check |
| XAPI evacuation may start before disable | new workloads can appear during drain | submit and reconcile `Async.host.disable` first |
| Proxmox exposes a stable REST maintenance mutation | undocumented/version-specific calls can break HA | drain-only; no shell fallback; capability remains explicit |
| XO host maintenance action matches XAPI | action name/schema can vary | plan/read only; mutation unsupported until runtime discovery and contract fixtures exist |
| cancel means rollback | already moved VMs stay moved | cancel stops future work only; UI and result state this explicitly |
| `drained` is completed history | scheduler could immediately target the host again | drained/maintenance retain an active reservation until explicit exit |
| a process is the only worker | duplicate replicas launch duplicate waves | leader gate, run lease and deterministic child idempotency keys |
| encryption failure is harmless | plan/native refs could leak or become unusable | reuse mandatory crypto utility; no plaintext fallback |
