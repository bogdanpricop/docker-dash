## Safety contract

- Residency categories are fixed. A site policy must declare at least one
  jurisdiction for all four categories and is always fail-closed. Once present,
  a store-and-forward plan requires a destination and records allowed evidence
  for every category in its immutable hash; one blocked category rejects the
  complete plan.
- The identity cache stores subject reference, external assertion digest,
  scopes, reason/ticket, expiry, signature and operator identity. Normal TTL is
  at most 15 minutes; emergency TTL at most five. The requester cannot activate
  the grant and no API representation contains a token or password.
- Vault and BMC records reject unknown secret-shaped fields and credential URLs.
  Only local endpoint, namespace, certificate fingerprint and secret reference
  metadata are persisted. Secret-resolution plans expire within five minutes.
- Single-node, quorum and reservation inputs are bounded observations. Their
  results declare `applySupported: false`; readiness never changes a cluster.
- Console profiles cannot enable clipboard or file transfer. The platform
  exposes no console launcher or session token for this edge-specific profile.
- Remote-hands and eligible BMC recovery plans create infrastructure approval
  records whose payload hash binds plan hash, target and expiry. Authorization
  requires the administrator who made the independent approval, exact typed
  target and a non-expired approval/plan.
- Destructive BMC actions require identity match, fencing, safe quorum,
  evacuated workloads and recent verified backup. Missing evidence yields a
  blocked plan with no approval request. A ready plan is still only a signed
  envelope for the edge agent; central provider mutation remains zero.

## Persistence and authorization

Migration `140_edge_sovereignty_resilience.js` adds sixteen `edge_*` tables and
two residency columns on synchronization plans. It grants four new site-admin
permissions for sovereignty, identity, resilience and BMC operations. The
governance permission catalog total becomes 65.

All new write routes remain admin-only, respect global read-only mode and emit
audit events that include hashes, decisions, safety state and explicit execution
location without secret values.

## Verification target

The focused B336–B345 suite covers fail-closed transfer blocking, hash-only
identity and four-eyes activation, local-vault secret plans, single-node safety,
quorum risk, reservations, console restrictions, remote-hands approval, BMC
inventory and safeguarded recovery. Existing B326–B335 tests run against the
combined schema. Full Jest, ESLint, syntax, migration and UI/API exposure checks
are required before tag and rollout.
