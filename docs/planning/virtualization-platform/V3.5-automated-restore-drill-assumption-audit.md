# V3.5 — Automated restore drill assumption audit

| Assumption | Verification | Disposition |
|---|---|---|
| Archive verification proves bootability | PBS explicitly recommends restore-and-boot testing in addition to verification | rejected |
| A unique MAC is sufficient isolation | It can still emit DHCP/ARP or reach production networks | rejected; every NIC must be link-down |
| Start can be retried safely after a lost response | Provider state may have changed after submit | rejected; reconcile state/task, otherwise unknown |
| Any stopped VMID can be deleted after a drill | VMID reuse or operator changes can violate ownership | rejected; exact marker, type, node, VMID, and stopped state required |
| Failed drills should always clean up | Failed targets contain useful forensic evidence and ownership may be ambiguous | rejected; retain failures |
| Arbitrary scripts are a normal assertion | They create an unbounded RCE and secret/output surface | rejected; fixed agent checks only |
| LXC has equivalent QEMU guest-agent evidence | PVE exposes different control surfaces | rejected; LXC boot-only is explicit |
| XO product support implies adapter support | Docker Dash has not conformance-tested XO restore mutation/tasks | rejected; capability remains fail-closed |
| Cron wake-up alone prevents duplicates | leaders can restart or overlap around a due minute | rejected; durable due-slot uniqueness plus idempotency |
| RTO includes cleanup | Cleanup speed is not service-recovery speed | rejected; assertion RTO and cleanup duration are separate |

## Provider-real promotion checks

1. Restore a disposable verified QEMU point into a reserved node/storage/VMID range.
2. Prove every original NIC shape is preserved except `link_down=1` and that no packet leaves the target.
3. Prove guest-agent required, optional, absent, late, and malformed-response behavior.
4. Interrupt the worker before and after restore, start, stop, and destroy submissions; prove no duplicate mutation.
5. Change/remove the marker before cleanup and prove deletion remains blocked with the target retained.
6. Exercise QEMU and LXC success, boot failure, forced-stop fallback, native task failure, cancellation, and timeout.
7. Run the same due slot from two leader candidates and prove one persisted operation.
8. Verify RPO/RTO/evidence hashes without exposing archive paths, storage native IDs, UPIDs, or credentials.
