# V2.4 — Assumption audit

| Assumption | Failure if false | Control |
|---|---|---|
| every provider uses quorum terminology | vSphere evidence is mislabeled | provider-specific signal reason; common key is coordination, not a fabricated native quorum |
| HA enabled means restart capacity exists | protected VMs cannot restart | separate admission/capacity/native-plan signals |
| memory alone proves failover | CPU, network, storage or device constraints block restart | simulation labeled conservative and estimated; explicit limitations |
| all powered-on VMs are HA protected | coverage is overstated | use native HA resource/priority evidence; unknown stays unknown |
| shared storage inventory proves every VM is portable | local or inaccessible disks are missed | shared-storage signal is domain-level only; placement limitation remains |
| fencing can be inferred from an online cluster | split brain risk is hidden | pass only from explicit provider evidence; otherwise unknown/not applicable |
| restart priority is a dependency graph | application recovery is promised incorrectly | render ordered groups only and label dependency readiness unknown |
| vCenter properties exist on standalone ESXi | SOAP calls fail or invent a cluster | product variant gate and unsupported snapshot |
| XO exposes all XAPI HA fields | empty fields are treated as healthy | projected optional fields become unknown evidence |
| snapshot history may contain native topology | provider identifiers leak at rest/API | canonicalize identities, encrypt payload, sanitize response |
| a scheduled refresh can run on every replica | provider load and duplicate rows multiply | leader gate, overlap guard and unique bucket |
| failure of one endpoint invalidates fleet history | one provider outage stops all sampling | bounded per-endpoint isolation and last-good retention |
