# V4.3b — Virtual network policy advisory feature specification

**Status:** planned for v8.29.0 (2026-07-28)

Network Policy Advisory evaluates the provider-visible virtual-network inventory
against a transient operator-selected baseline. Accessibility is always required;
the operator may additionally require a minimum MTU, managed-network evidence,
and a reported VLAN identifier.

`GET /api/providers/:hostId/network-policy-advisory` is host-view scoped and
requires the additive `network.policy.read` capability. It accepts `minMtu`
(576–65535), `requireManaged`, and `requireVlan`. The response contains canonical
network identities, provider-neutral signals, compliant/noncompliant/unknown
counts, and explicit limitations. Inventory reads are bounded to 500 networks.

The policy is neither stored nor applied. It sends no traffic, reserves nothing,
does not modify virtual switching, and has no CLI fallback or remediation path.
Missing provider evidence remains `unknown`; it never becomes compliant.

Initial support is conditional for vSphere and Xen management planes. Proxmox is
explicitly unsupported until its safe common virtual-network inventory contract is
available.
