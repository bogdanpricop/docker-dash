# V1.9 — Uniform VM disk and NIC inventory

## Outcome

The common VM detail page exposes bounded, vendor-neutral disk and NIC inventory for Proxmox VE, VMware vSphere/ESXi, Xen Orchestra, direct XAPI, and standalone Xen (`xl`/legacy `xm`). Native device identifiers remain server-side and every returned device receives an opaque Docker Dash identifier.

## Scope

- B076: disk bus, device, capacity, allocation, provisioning, backing storage, attachment, and boot/read-only state.
- B101: NIC model, MAC, network/bridge/VLAN, guest addresses, MTU, link state, security, and QoS where the provider reports them.
- B085–B086 read-model foundation: storage placement and allocated/capacity totals are represented without claiming fleet-wide overcommit when the provider cannot prove it.
- Per-device `hotPlug`, `hotUnplug`, `onlineResize`, and `connectDisconnect` evidence is tri-state (`true`, `false`, or `null`). `null` means unverified, never implicitly supported.

## Explicitly deferred

Disk/NIC create, attach, detach, delete, resize, move, conversion, storage-policy assignment, VLAN/trunk/overlay creation, and any other mutation remain in V4.1 and V4.3 with intent diff, confirmation, policy, and rollback gates.

## Acceptance

1. A hardware read failure never hides cached VM overview, power, snapshot, or activity data.
2. Responses are capped, sanitized, and contain no provider credentials or native opaque references.
3. Unsupported sections explain the capability or provider read failure.
4. All five Xen/vSphere/Proxmox management variants have contract and parser coverage.
5. The UI renders accessible disk and NIC tables and preserves an honest empty/unavailable state.
