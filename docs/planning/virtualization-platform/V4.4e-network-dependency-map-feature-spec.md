# V4.4e — Network dependency map

**Backlog:** B118
**Status:** local implementation complete; browser/provider evidence/release pending
**Scope:** bounded read-only correlation of normalized network and relationship evidence

## Outcome

Administrators can build an immutable, time-bounded map that correlates
normalized flow batches, IP ownership observations, DNS records, typed metadata
and explicit relationship graphs. Every edge exposes its sources, first/last
seen timestamps, confidence, freshness and whether it is eligible for impact
analysis.

## Evidence semantics

- Explicit relationship graph edges use the existing contract: source is an
  upstream dependency and target is the resource it may impact.
- `dependency.upstream` and `dependency.requires` metadata values declare the
  same upstream-to-downstream direction. Confidential metadata is excluded.
- Allowed flow evidence is reversed from client→server traffic into a possible
  server→client impact direction, but remains `observed`, causality is
  `unproven`, and it is excluded from impact traversal unless confirmed by a
  declared source.
- IP evidence resolves a flow endpoint only when exactly one resource owns the
  address. Conflicting ownership remains unresolved and is counted explicitly.
- DNS evidence attaches bounded aliases to a proven resource/address mapping;
  DNS alone never creates a resource dependency.
- Temporal proximity, shared application metadata, denied traffic and missing
  evidence never become causal dependencies.

## Persistence and bounds

- Address and DNS observation batches are immutable and hash-deduplicated.
- Dependency snapshots store canonical nodes/edges, source cursors and a
  deterministic hash; rebuilds with identical evidence deduplicate.
- Source batches are bounded, retained/expiry-aware, and maps cap nodes, edges,
  traversal depth and encoded response size.
- Fresh/stale is evaluated against an operator-selected threshold; stale edges
  stay visible instead of disappearing or being represented as current.

## API and UI

- Admin-only normalized address/DNS observation ingestion and snapshot build.
- Latest map and recent snapshot metadata are included in Network Advanced.
- A read-only impact endpoint returns upstream/downstream declared traversal and
  separately reports observed candidates excluded from causal impact.
- UI shows edge basis, confidence, freshness, source evidence and bounded
  upstream/downstream inspection.

## Safety

- No packet capture, DNS query, ping, guest command, provider call, mutation,
  remediation or policy enforcement is initiated.
- No raw packet payload or credentials are accepted or stored.
- Native provider references and confidential metadata are not exposed.

## Acceptance evidence

- source correlation and deterministic dedupe;
- ambiguous IP ownership never resolves silently;
- DNS-only and flow-only evidence remain non-causal;
- declared edges drive cycle-safe bounded impact traversal;
- expiry/freshness and denied-flow handling;
- strict input/secret rejection and size bounds;
- API audit, UI contract, focused tests, lint and registry reconciliation.
