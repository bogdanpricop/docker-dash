# V4.1 — Volume lifecycle rollout results

## Outcome

V4.1 shipped in functional commit `c2a2a6b`, tagged `v8.22.0` and pushed to
`agent/advanced-compose-gitops`. The release makes the common VM disk inventory actionable through
reviewed create-and-attach, retain-on-detach, grow-only resize and supported storage move operations.
It introduces durable Docker Dash-managed volume ownership and keeps permanent backing deletion behind
its own disabled-by-default release flag.

The release is deployed and healthy on the LAN Docker host and the public VPS. Docker Desktop was not
installed on the development workstation, so no local container deployment was attempted.

## Validation evidence

- full local suite: 237 suites passed, 2,769 tests passed and 4 skipped (2,773 total);
- focused V4.1 suites: 4 suites and 9 tests passed after the final lint cleanup;
- `eslint src/`: zero errors and the 13 pre-existing warnings; V4.1 added none;
- `git diff --check`: clean before the functional commit;
- `provider_managed_volumes` migration `122_provider_managed_volumes.js` is the latest migration on
  both remote databases, and its table is readable with zero initial rows;
- both `DD_PROVIDER_VM_DISK_LIFECYCLE` and `DD_PROVIDER_VM_DISK_DELETE` are disabled in the running
  containers. No provider mutation was submitted as part of this rollout.

## Production gate

The release is code-complete but the disk lifecycle is not enabled anywhere by default. Before a
provider endpoint is allowed to mutate a disk, enable only
`DD_PROVIDER_VM_DISK_LIFECYCLE=true` on the chosen canary, perform a disposable-disk preflight and
operation smoke, then collect the provider task and post-read audit evidence. Do not enable
`DD_PROVIDER_VM_DISK_DELETE` in that first canary; it is a separate destructive-release decision.
