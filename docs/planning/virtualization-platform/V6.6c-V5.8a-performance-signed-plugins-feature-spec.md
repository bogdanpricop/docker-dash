# V6.6c / V5.8a — Advanced performance and signed provider plugins

**Release:** v8.72.0

**Backlog:** B396–B405

**Date:** 2026-07-30

## Outcome

This batch closes the hardware/performance backlog and establishes the first
five provider-plugin controls. Performance results remain evidence/advisory;
plugins fail closed before enablement and arbitrary plugin code is not loaded.

## Performance evidence

- B396 compares recorded VM vCPU, memory, required CPU features and virtual
  device kind/model against the latest target hardware/device snapshots plus
  provider type/version requirements. Results are immutable and hash-bound.
- B397 accepts only explicitly controlled benchmark runs and retains suite,
  metric, direction, score/unit, run configuration and source hardware evidence.
- B398 correlates a contended workload with same-host, same-window peer CPU,
  queue and memory pressure. Confidence is bounded and the response explicitly
  states that correlation does not prove causation.
- B399 compares compatible baseline/candidate metrics according to their
  higher/lower-is-better direction and stores change reference, threshold,
  delta and regression percentage.
- B400 supplies batch/database/VDI/latency/AI presets with bounded overrides and
  evaluates latest samples. Profiles set `applyEndpoint: null` and
  `providerMutationsStarted: 0`.

## Plugin trust boundary

- B401 verifies a detached Ed25519 signature over canonical JSON. The manifest
  declares plugin/version, core range, API/schema, permissions, provider
  capabilities and the declarative JSON-stdio RPC contract.
- B403 classifies declared read/write/mutation/secret/network permissions and
  persists grant/deny consent against the exact manifest hash. A new manifest
  disables the plugin and does not inherit old consent.
- B404 checks signature, core range, API/schema, capability catalog and every
  consent before enable; any failure blocks enablement.
- B402 provides a real subprocess boundary for fixed control-plane probes:
  32 MiB V8 heap, two-second timeout, 16 KiB output, empty environment and a
  temporary working directory. The worker loads no plugin code, receives only
  hashes/counts, invokes no plugin endpoint and never returns request payloads.
- B405 accepts only timestamp, latency and request/error/crash aggregates.
  Unexpected and credential-shaped fields fail closed; raw errors and payloads
  are never stored.

## Persistence and authorization

Migration 146 adds five performance tables, four provider-plugin tables and two
governance permissions (`hardware_advanced.manage` and
`provider_plugins.manage`). Administrator-only APIs and the Hardware / Provider
Plugins tabs expose the controls; every accepted write is audit logged.
