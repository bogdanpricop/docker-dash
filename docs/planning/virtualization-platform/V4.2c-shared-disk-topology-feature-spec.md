# V4.2c — Shared virtual-disk topology feature specification

**Status:** shipped in v8.25.0 (2026-07-28)

## Outcome

Storage Posture can read a bounded projection of virtual-disk backings used by
more than one observed VM. The projection is provider-neutral and read-only for
Proxmox VE, vSphere / ESXi and supported Xen management planes.

## Safety contract

1. The API exposes no provider-native VMDK, VDI, volume, storage or file-path
   reference. Backing identifiers are host-scoped opaque hashes.
2. A common backing is **confirmed shared** only if every observed attachment
   carries the provider's explicit `shared=true` declaration. Any other common
   backing is returned as **review** evidence, not a valid shared-write claim.
3. Collection reads at most 100 selected VMs and executes at most four VM
   hardware reads concurrently. A response declares partial coverage whenever
   selection is truncated, a hardware read fails, or disk inventory is absent.
4. The endpoint is gated by `storage.sharedTopology.read` and fails closed when
   the provider or required live inventory is unavailable.
5. This slice performs no disk/storage mutation, guest action, test write,
   repair, policy/QoS change, provider CLI fallback or automatic remediation.

## API

| Method | Path | Access | Effect |
|---|---|---|---|
| `GET` | `/api/providers/:hostId/storage-topology` | host view | bounded live read-only evidence |

## Explicit exclusions

- validation that a clustered filesystem or application supports concurrent writers;
- provider storage lock or multipath diagnosis, backing repair and snapshot remediation;
- unbounded inventory scans, native-reference export, scheduling or mutation.
