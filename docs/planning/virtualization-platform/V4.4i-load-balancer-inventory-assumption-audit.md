# V4.4i — Load balancer inventory assumption audit

| Assumption | Evidence / decision | Result |
|---|---|---|
| A configured member is healthy | Admin state and health-check state are independent | Rejected; preserve both |
| One VIP has one listener | Providers support many protocols/ports per VIP | Rejected; model bounded listener sets |
| A listener may reference any pool key | Cross-object mistakes create misleading topology | Rejected; references must resolve in the same LB |
| Provider `active` proves every member is healthy | Partial pool degradation can coexist with an active LB | Rejected; compute member-health summary separately |
| Missing coverage is an empty inventory | Unobserved LBs/members may exist | Rejected; incomplete remains unknown |
| Native provider refs should be shown for linking | Refs may expose tenant/infrastructure details | Rejected; accept canonical opaque link keys only |
| Inventory collection may run health probes | This changes traffic and destination risk | Rejected; imported evidence only |
| B123 should include NAT/public-IP mutation | Allocation and release require ownership/quota guards | Rejected; B124 stays separate |
