# V4.2g — Stale snapshot growth monitor feature specification

**Status:** implementation in progress
**Backlog:** B090
**Provider scope:** Proxmox, vSphere and Xen common snapshot inventory
**Provider effect:** read-only

## Outcome

Docker Dash exposes a bounded host-level assessment of snapshot age, chain
depth, provider-reported bytes, day-over-day byte growth, graph integrity and
vSphere consolidation state. It stores one summary observation per endpoint and
UTC day, displays trend history in Storage Posture and raises a notification
only when a previously observed snapshot enters a worse warning/critical state.

## Evidence contract

- Age is calculated only from a valid provider snapshot creation timestamp.
- Chain depth is calculated only from the canonical parent graph. A missing
  parent or a truncated graph is reported as incomplete evidence.
- `estimatedBytes` is populated only when the provider adapter reports a
  bounded non-negative byte value. VM disk capacity is never substituted for
  snapshot delta size.
- Growth is calculated against the latest observation from an earlier UTC day.
  No prior size means `growthPercent=null`, not zero growth.
- Consolidation risk is set only from vSphere
  `runtime.consolidationNeeded=true`; snapshot presence alone does not imply it.
- Integrity `cycle` or `orphan_parent` is critical evidence.

## Default thresholds

Thresholds are conservative and host-overridable by an administrator:

| Provider | Warning age | Critical age | Warning depth | Critical depth | Warning growth | Critical growth |
|---|---:|---:|---:|---:|---:|---:|
| vSphere | 3 days | 14 days | 3 | 8 | 20% | 50% |
| Proxmox | 7 days | 30 days | 3 | 8 | 20% | 50% |
| Xen | 7 days | 30 days | 3 | 8 | 20% | 50% |

The policy is versioned. Updates require admin, host scope, global writable mode
and audit. The monitor never deletes, consolidates or modifies a snapshot.

## API

| Method | Path | Access | Effect |
|---|---|---|---|
| `GET` | `/api/providers/:hostId/snapshot-risk` | host view | cached assessment + daily trend |
| `POST` | `/api/providers/:hostId/snapshot-risk/refresh` | admin + host view | bounded provider refresh, observation and transition evaluation |
| `PUT` | `/api/providers/:hostId/snapshot-risk/policy` | admin + host view | update thresholds only |

The leader runs the same refresh every six hours. One unavailable endpoint or VM
does not block the rest; partial coverage is explicit and retained in the
observation.

## Persistence

- `provider_vm_snapshots.size_bytes` stores optional provider-reported bytes;
- `provider_snapshot_risk_policies` stores versioned per-host thresholds;
- `provider_snapshot_risk_observations` stores one bounded UTC-day summary and
  prior-size projection;
- `provider_snapshot_risk_states` stores the last severity/fingerprint used for
  transition-only notification dedupe.

## Alerting

- The first observation establishes a baseline and does not notify.
- `healthy|unknown → warning|critical` and `warning → critical` notify once.
- An unchanged persistent problem does not notify again.
- Recovery updates the state silently, allowing a future regression to notify.
- Audit and notification payloads contain canonical IDs, counts and severity;
  no native reference, raw provider payload or credential is persisted.

## UI

Storage Posture receives a Snapshot risk section with:

- state counts, oldest age, maximum proven chain depth and byte coverage;
- current warning/critical snapshots linked to the common VM detail page;
- explicit partial/stale evidence messaging;
- daily state/byte trend;
- an admin policy editor and explicit refresh control.

## Explicit exclusions

- automatic snapshot deletion, consolidation or retention changes;
- inferring snapshot bytes from VM provisioned/allocated disk capacity;
- filesystem, guest-agent or datastore scans;
- unbounded fleet polling;
- treating a snapshot as an independent backup.
