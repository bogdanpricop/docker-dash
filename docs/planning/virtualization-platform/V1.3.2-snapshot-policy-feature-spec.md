# V1.3.2 Feature spec — Snapshot policy and retention

## Obiectiv

Un administrator poate defini o singură policy portabilă per VM pentru snapshot-uri programate și retenție, fără ca un cron volatil să execute direct mutații. Policy runner-ul leader-only creează exclusiv operații durabile `vm.snapshot`; progresul orchestration rămâne persistent și poate fi reluat după restart.

## Scope

- policy host+VM cu frecvență `hourly`, `daily` sau `weekly`, evaluată UTC;
- minute limitat la `0/15/30/45`, plus hour/weekday când frecvența o cere;
- create crash/quiesced prin același live preflight V1.3.1;
- prefix de ownership, nume determinist per slot și duplicate guard;
- `retainCount`, `maxAgeDays` și `maxDeletesPerRun` bounded;
- retention numai pentru snapshot-uri create cu prefixul policy;
- current, manual, child-bearing, invalid-graph și timestamp-less snapshots protejate;
- dry-run implicit, feature flag separat implicit off pentru automation execute;
- persistent policy runs care așteaptă create success înainte să trimită cel mult o ștergere leaf la un moment dat;
- CRUD, preview, manual run, history, audit și UI în tab-ul Snapshots;
- leader gate și overlap guard prin infrastructura background jobs existentă.

## Anti-scope

- policy nu reprezintă backup, GFS, immutability, off-host copy sau recovery verification;
- nu adoptă și nu șterge snapshot-uri manuale;
- nu execută delete subtree și nu ocolește child guard;
- nu implementează memory checkpoints;
- nu folosește VMSS/Xen provider-native ca sursă autoritativă; contractul comun rămâne identic pe provider;
- bulk/fleet policy intră după canary single-VM.

## Acceptance

- policy nouă este disabled + `dry_run` dacă operatorul nu cere explicit altfel;
- `execute` + enabled cere confirmare și numele exact al VM-ului;
- dezactivarea globală `DD_PROVIDER_VM_SNAPSHOT_AUTOMATION` blochează orice operație nouă;
- același UTC slot nu poate crea două policy runs;
- restartul dintre create și retention continuă din DB, fără replay create;
- cel mult o mutație este activă per VM și retention nu începe înainte de create success;
- un child operation `unknown` face policy run `unknown` și păstrează blocajul VM;
- preview și history nu expun native refs;
- scheduled dry-run nu creează provider operations;
- UI repetă explicit că snapshot-urile nu sunt backup-uri.
