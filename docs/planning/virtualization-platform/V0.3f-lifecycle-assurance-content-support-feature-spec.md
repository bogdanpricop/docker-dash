# V0.3f — Lifecycle assurance, content and support

**Release:** v8.59.0  
**Backlog:** B266–B275  
**Date:** 2026-07-29

## Outcome

V0.3f closes the lifecycle and configuration-management research section.
Renewal, mirror synchronization, collection and validation are adapter-only;
missing adapters remain explicit. Stored documents are bounded, canonical and
secret-free or secret-redacted before hashing. No function falls back to a
provider CLI, arbitrary shell, direct download or implicit remediation.

## Data model and permissions

Migration 133 adds nineteen stores: certificate renewal jobs; entitlement,
assignment, usage, policy and alert records; configuration snapshots, diffs,
drift policies/assessments and host profiles/assessments; air-gap mirrors,
artifacts and runs; support bundle requests/nodes; and validation packs/runs.

Four site-admin permissions are added: `lifecycle_renewal.manage`,
`license_entitlement.manage`, `configuration_assurance.manage` and
`lifecycle_support.manage`. Combined with V0.3e, the governance catalog now has
40 permissions in the production migration sequence.

## Renewal behavior

A renewal plan binds ownership, adapter, approved maintenance dependency,
previous fingerprint and rollback policy into a stable hash. Planning with no
registered adapter produces `unsupported`. Approval requires the hash and typed
phrase. Execution additionally requires an approved `certificate.renew`
request whose payload hash binds the renewal job, an active/succeeded durable
provider operation and a second typed phrase.

The adapter receives only bounded, secret-free input. Apply evidence is stored
before verify. Successful verification must return a future expiry and SHA-256
fingerprint before tracked certificate evidence changes. Failure follows the
approved rollback policy and retains previous certificate evidence.

## License and configuration behavior

Entitlements contain opaque contract references, never license values. Usage is
point-in-time evidence. Alert fingerprints make repeated evaluations idempotent;
forecast uses the two newest observations and clearly remains a simple linear
estimate.

Snapshots redact recursively before canonicalization. Diffs operate on stable
field paths. Drift precedence is ignored, denied, allowed, then review. Host
profiles compare exact expected values; missing evidence stays unknown and all
suggested remediation is labeled for explicit durable-operation review.

## Content, support and validation behavior

Mirror definitions retain site, adapter-owned root reference, capacity and
trusted signature identities. A sync adapter cannot add an unrequested digest,
an untrusted identity, an unverified signature or content beyond mirror
capacity. There is no direct fetch fallback.

Support collectors are allowlisted and invoked per node. Their result is
bounded, recursively redacted, individually hashed, joined into a checksummed
manifest and assigned an expiry. Validation packs use only registered probes;
required missing probes fail closed and the result reports zero mutations.

## Control surface and verification

Governance → Lifecycle & updates exposes every planner, approval, inventory,
policy, comparison, mirror, bundle and validation action. All mutations are
audited, including explicit zero-mutation counts where relevant.

The dedicated 13-test suite covers all nineteen stores, permissions and grants;
unsupported and successful renewal plus rollback; opaque license inventory and
all alert classes; secret redaction/deduplication; diff, drift and host-profile
assessment; signed and unsigned mirror behavior; redacted multi-node bundles;
and six-category validation fail-closed behavior.
