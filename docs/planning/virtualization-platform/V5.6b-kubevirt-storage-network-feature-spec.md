storage/network resources needed to run those VMs. It adds CDI and template
creation workflows plus read-only convergence views for migration, node drain,

## Guarded creation protocol

DataVolume creation and VM template instantiation share one fail-closed
protocol:

1. Validate DNS-compatible identity, source and bounded resource quantities.
2. Reject inline password, token, private-key and cloud-init/network-data fields.
3. Resolve the namespace, StorageClasses, source PVCs and Multus NADs against the
   target API server.
4. Submit the complete object with `dryRun=All` and retain only bounded server
   acceptance evidence.
5. Persist the canonical manifest, prerequisites, desired hash and plan hash.
6. Create an infrastructure approval whose payload hash contains that exact
   plan identity. Approval never starts execution.
7. Require an approval decision by an administrator other than the requester
   and typed confirmation equal to the resource name.
8. Re-read every prerequisite and repeat `dryRun=All`; any evidence difference
   makes the plan stale.
9. Claim a unique `kvop_…` operation, persist queued/running events, create once,
   then GET the resource and verify its manifest fingerprint.
10. Persist succeeded/failed evidence. A replay of an executing operation may
    reconcile only a resource bearing the exact fingerprint.

There is no update/delete path, no arbitrary YAML apply, no implicit execution
after approval and no fallback when CDI, KubeVirt or prerequisite APIs are
unavailable.
