# V0.2b / V1.5b / V1.7b — Platform foundation and content lifecycle

**Release:** v8.75.0

**Backlog:** B011, B012, B016, B017, B019, B020, B023, B034, B036, B038, B039, B040

**Date:** 2026-07-30

## Outcome

This batch closes the remaining inventory extensibility and reusable image /
provisioning contracts. Every write is administrator-only, bounded, audited and
hash-bound. Provider/data-plane execution is explicitly separate.

## Inventory contracts

- B011 normalizes provider events with severity, stable fingerprint, native
  identity and provider cursor. Replays deduplicate; cursor reuse with different
  evidence fails closed.
- B012 records hash-only added/updated/removed deltas. The previous cursor must
  equal the latest committed cursor for that provider and resource type.
- B016 stores versioned collections using `equals`, `contains`, `in` and bounded
  regex selectors over kind/name/provider/site/state/tag.
- B017 supplies string/integer/boolean/enum/URL/date schemas and typed resource
  values. Schema and value updates require optimistic version matches.
- B019 validates canonical graph endpoints and calculates cycle-suppressed,
  depth-bounded downstream impact.
- B020 reports missing owners, detached disks and images/templates unused for at
  least 30 days. It has no cleanup endpoint.
- B023 turns remaining quota, reset evidence, latency, error rate and in-flight
  requests into available/degraded/exhausted state and a bounded concurrency cap.

## Provisioning and content contracts

- B034 linked-clone plans gate provider capability, shared backing, chain depth,
  same-storage requirements and source snapshot state; no clone is submitted.
- B036 profiles are immutable by semantic version, reject passwords/scripts/
  commands/private keys and keep only provider-native secret references.
- B038 ranks offerings that meet common CPU/RAM/disk/GPU/architecture needs and
  explains every rejected candidate.
- B039 records cross-provider image/template observations with public canonical
  IDs, digest grouping and bounded provenance; native references are excluded.
- B040 creates a resumable receipt ledger with aligned chunk offsets/sizes/hashes,
  complete coverage validation, expected whole-file SHA-256 and an optional
  qemu-img conversion contract. Image bytes are held by an approved external
  data plane, not by this control plane.

## Persistence and authorization

Migration 149 adds fourteen tables and the permissions
`platform_inventory.manage`, `platform_metadata.manage` and
`platform_content.manage`. The Governance Platform Foundation tab exposes
capability, ledger, recent event and image-session evidence.

## Safety boundary

The route surface has no execute/apply/start-import endpoint. Hygiene never
deletes; receipt sessions store zero bytes; linked clone, conversion and import
remain plans for a separately approved adapter.
