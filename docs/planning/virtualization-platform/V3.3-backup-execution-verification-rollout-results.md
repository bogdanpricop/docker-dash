A second invocation used an invalid SQL verification expression and also restored the previous container. The successful invocation completed every release and verification gate; a CRLF in the final trap-removal line caused only the already-finished SSH command to exit non-zero, with the success guard set, so no rollback ran. Independent follow-up probes confirmed the intended image, migration, flags, container health, HTTP behavior, and database state.

Rollback anchors remain the immutable prior release/image plus the verified online SQLite backup above. Backup execution does not authorize or perform retention deletion.
