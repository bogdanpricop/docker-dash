# V1.7 Feature spec — Linux guest customization

**Status:** implemented and validated, release-gated; rollout pending

**Backlog mapping:** B035 structured subset shipped; B036 foundation only; C028/C029 partial Linux coverage

## Outcome

An administrator can optionally attach a structured, passwordless Linux guest customization to the existing create-from-template workflow. The same preflight shows provider capability, accepted fields and blockers before the operation is queued.

The first slice accepts hostname, DNS domain, IANA-style timezone, Linux user, OpenSSH public keys, DHCP or static IPv4, gateway, DNS servers and search domains. It deliberately rejects passwords, private keys, arbitrary user-data, scripts, commands and unknown fields.

## Provider matrix

| Provider | Execution | Constraints |
|---|---|---|
| Proxmox VE | native Cloud-Init QEMU config after clone, then read-back verification | hostname equals VM name; timezone is not mapped in this slice; compatible Cloud-Init template required |
| vSphere/ESXi | `CustomizationLinuxPrep` embedded in `CloneVM_Task`, preceded by `CheckCustomizationSpec` | DNS domain required; no user/SSH-key creation; guest customization support/tools required |
| Xen Orchestra | discovered `/rest/v0/pools/{id}/actions/create_vm` async route with `cloud_config` and `network_config` | full clone, template pool default storage, Cloud-Init-ready template |
| direct XAPI | blocked | no verified portable config-drive upload transport |
| raw Xen xl/xm | blocked | no management-plane guest customization contract |

## UX and API

The VM Catalog create dialog exposes an optional Linux identity/network panel. Preflight and submit reuse:

- `POST /api/providers/:hostId/artifacts/:artifactId/clone/preflight`;
- `POST /api/providers/:hostId/artifacts/:artifactId/clone`.

The additive request field is `customization`. Preflight returns only a safe summary and SSH SHA-256 fingerprints; the operation request remains encrypted by the durable operation engine. Audit events contain enabled state, hostname and network mode, never public-key material.

Both `DD_PROVIDER_VM_PROVISIONING=true` and `DD_PROVIDER_VM_GUEST_CUSTOMIZATION=true` are required. The new flag defaults to false.

## Acceptance

- strict schema rejects unknown fields, passwords, commands, invalid network data and unsupported OS families;
- plan hash includes the safe customization semantics;
- provider capability is discovered live and fails closed;
- Proxmox interrupted config submission is recovered through idempotent desired-state read/apply/verify;
- vSphere rejects an incompatible spec before disk copy;
- Xen Orchestra returns a durable task ID and is reconciled through Activity Center;
- operation result and audit output contain no raw SSH keys;
- VM remains powered off; customization completes on the first operator-controlled boot.

## Deferred

Reusable/versioned profiles and secret references (remainder of B036), Windows Sysprep, IPv6, multi-NIC mapping, raw user-data, packages/scripts, template readiness probes and guest-side completion evidence are separate gated batches.
