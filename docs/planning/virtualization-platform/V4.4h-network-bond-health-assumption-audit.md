# V4.4h — Bond/LAG health assumption audit

| Assumption | Evidence / decision | Result |
|---|---|---|
| Every link-up member forwards traffic | Standby, individual and non-distributing LACP members can be link-up | Rejected; active role is explicit |
| Equal link speed proves balanced traffic | Hashing and workload locality can concentrate traffic | Rejected; use bounded traffic deltas and report spread |
| Zero traffic means balance | There is no distribution sample to compare | Rejected; imbalance is `not_observed` |
| One LACP partner key is enough | Members can attach to different partner systems/keys | Rejected; compare all active member partner evidence |
| A recent failover is necessarily unhealthy | Planned maintenance and recovery can both cause failover | Rejected; preserve event evidence and warn without guessing cause |
| Missing member inventory means the bond is healthy | Hidden/down members can invalidate redundancy | Rejected; incomplete coverage is unknown |
| Health analysis may toggle a link to test failover | It risks management and storage loss | Rejected; zero active failover or mutation |
| B121 needs a second PF/VF store | B122 already owns normalized PF/VF evidence | Rejected; reuse/link later, never duplicate |
