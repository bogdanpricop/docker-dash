# V4.2f — Advanced storage control plane

**Release:** v8.78.0

**Backlog:** B082–B084, B087–B089, B091–B095, B097–B100

## Outcome

This release closes fifteen storage research items through a single audited
control plane. It introduces eleven persistent contracts and reuses the two
provider flows that were already complete: native vSphere snapshot
consolidation (B091) and opaque shared-disk topology (B094).

## Persistence and authorization

Migration 151 creates eleven append/update ledgers for conversion, policy,
latency, path, cleanup, QoS, tiering, object-storage, suite-health and general
change evidence. Three governance permissions are registered:
`storage_content.manage`, `storage_policy.manage` and `storage_health.manage`.
All write routes require an authenticated admin, writeable mode and an audit
record. Repeated canonical evidence returns the existing record.

## Safety boundary

- Strict request schemas reject unexpected and secret-shaped fields.
- Arrays, identifiers, timestamps, numbers and SHA-256 evidence are bounded and
  canonicalized before hashing.
- Unknown suite components, replication or backup-target state fail closed as
  `unknown`; failures take precedence over degradation.
- Secret values are never accepted. Object-storage credentials remain external
  references using an approved secret-manager URI.
- The new surface exposes no execute, apply, delete, cleanup or probe endpoint.
  Provider mutations, cleanup operations and network calls remain zero.
- Native consolidation and managed-volume/shared-topology flows keep their own
  existing approvals, capability gates and durable-operation safeguards.

## Operator surface

The Governance page includes an Advanced Storage tab with all fifteen
capabilities, latest suite-health evidence, object-store status and record
counts. It deliberately offers observation and plan visibility only; execution
requires an established guarded executor or a separately reviewed adapter.
