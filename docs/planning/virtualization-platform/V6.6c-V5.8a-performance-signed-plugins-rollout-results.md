Each backup was produced with the running application's `better-sqlite3`
online backup API, copied out of the container, copied into a writable `tmpfs`
and checked with `PRAGMA quick_check` in a networkless container with a
read-only root filesystem using the previous release image.

The first LAN attempt stopped before release extraction, build or container
switch because SQLite could not open auxiliary files beside a backup mounted
directly read-only. The backup was then verified through the isolated `tmpfs`
flow. A later LAN post-deploy probe used the wrong table name (`permissions`
instead of `governance_permissions`), so the automatic rollback restored the
healthy 8.71.0 container. The corrected probe then completed the 8.72.0
rollout. Both stops were verification-harness issues; the final independent
checks confirmed the intended runtime and persistent schema.
