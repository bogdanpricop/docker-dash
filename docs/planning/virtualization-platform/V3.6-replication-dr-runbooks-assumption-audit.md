# V3.6 — Replication and DR runbooks assumption audit

| Assumption | Counterexample | Contract decision |
|---|---|---|
| a storage replica is a complete DR plan | PVE replication is intra-cluster and has no application/network cutover contract | label scope exactly; failover mutation unsupported |
| vCenter credentials can run SRM | VMware Live Recovery has separate product, licensing, pairing and recovery-plan state | ordinary vSphere adapter is fail-closed |
| an XO backup archive is a running replica | full/incremental replication and backup archives have different recovery paths | strategy/evidence type remains explicit |
| VM boot order alone represents an application | DNS, databases, queues and external services create a dependency DAG | persist and validate explicit edges plus stages |
| newest backup is recoverable | creation time says nothing about verification | only `verified` points satisfy RPO evidence |
| a successful VM restore proves application recovery | guest boot/agent can pass while the service is unusable | report VM-level assertion scope and never claim app SLA |
| test duration equals production RTO | bubble-network setup, DNS and human decisions differ | measured drill RTO is labeled and production RTO remains an objective |
| manual acknowledgement is automated evidence | an operator can attest without machine-verifiable proof | source is explicit and does not satisfy automated compliance |
| unplanned failover can start before fencing | the original site may still serve writes | fencing/isolation is a hard blocker |
| failback is failover in reverse | reverse synchronization and reprotect change data authority | compile a distinct workflow and evidence gates |
| network mapping is harmless metadata | an incorrect cutover can cause outage or duplicate IPs | canonical mapping, V4 ownership dependency, no mutation here |
| deleting a group should delete its history | audit/compliance evidence would disappear | soft-delete group; retain immutable runs |
| one missing member can be ignored | an application dependency can be the critical path | worst-member compliance and explicit blocker |
| cross-endpoint access follows source access | recovery endpoint may belong to another tenant | admin-only mutation and both endpoint IDs preserved for later dual-scope RBAC |

## Audit probes

1. Create a valid three-tier graph and assert deterministic order across repeated plans.
2. Reject self-edge, cycle, missing dependency and later-stage dependency.
3. Reject source/recovery canonical identities owned by the wrong endpoint or kind.
4. Prove a recent unverified point does not satisfy RPO.
5. Prove a plan-only rehearsal does not turn `never_tested` into `met`.
6. Prove unavailable real failover/failback/test capabilities fail before persistence.
7. Prove provider replication inventory never exposes native job IDs, VMIDs, tokens or endpoints.
8. Prove soft deletion retains rehearsal evidence and excludes the group from active lists.
9. Verify route RBAC, feature flag behavior, typed errors and canonical audit payloads.
10. Verify evidence hashes change when dependency order, mappings or measurements change.
