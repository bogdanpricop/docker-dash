# V3.2 — Assumption audit

| Assumption | Evidence / treatment | Status |
|---|---|---|
| A VM snapshot is a backup | Explicitly rejected in UI, API plan, and existing snapshot contract | rejected |
| A repository found in SQLite is currently usable | Preflight requires the current live, host-scoped V3.1 response; no stale fallback | rejected |
| Missing capability means support | Required security controls block on false **and** unknown | rejected |
| Encryption intent proves encrypted data | Recovery-point evidence remains separate; intent is not promoted | rejected |
| A key can be stored in the policy | Only a bounded alias/vault path is accepted; key material patterns are invalid | rejected |
| Proxmox and XO have identical GFS semantics | Vendor difference is documented and emitted as a Xen warning | rejected |
| The common preview may prune | `mutationAuthorized:false`; V3.2 has no provider mutation edge | rejected |
| Arbitrary cron is necessary | Bounded recurrence plus IANA timezone covers the current requirement and is testable | narrowed |
| DST cannot duplicate schedules | Wall-clock slot key plus DB uniqueness deduplicates fallback repeats | controlled |
| Every selected VM has a stable ID | Transient identities are excluded and reported | rejected |
| Missing explicit workloads should block all policy authoring | Warning; disabled desired state may be retained for later repair | narrowed |
| An enabled blocked policy is acceptable | Create/update rejects it; runtime drift can still yield a recorded blocked slot | rejected |
| Disk labels can be enforced portably today | Stored as intent and warned; native resolution is deferred to V3.3 | rejected |
| An endpoint outage can be skipped silently | Scheduler persists a sanitized blocked plan for the due slot | rejected |
| More than 500 VMs/points are fully evaluated | Bounded inventories emit explicit truncation warnings | rejected |
| Verification capability proves restorability | It is only evidence; restore drills remain a later batch | rejected |
| Policy deletion should erase history | Soft deletion preserves plan evidence | rejected |
| Viewers need policy mutation access | Reads only; authoring and manual planning are admin + operate | rejected |

## Residual risks accepted for V3.2

- A provider may change inventory immediately after preflight. V3.3 must revalidate immediately before mutation.
- Label normalization quality depends on each provider adapter. Explicit canonical selection remains available.
- `Intl` timezone data follows the Node runtime image. Runtime upgrades must retain schedule regression tests.
- Portable GFS preview does not model every native interaction between overlapping tiers. It is advisory until a V3.3 translation is selected.
- A key-reference alias can still reveal naming conventions to authorized viewers; it contains no key material and is host-policy metadata.
- A scheduled blocked plan consumes its due slot instead of retrying within the same slot. This avoids duplicate execution intent and makes the missed schedule explicit.
