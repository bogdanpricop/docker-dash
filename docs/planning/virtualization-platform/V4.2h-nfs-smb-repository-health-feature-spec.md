# V4.2h — B096 NFS/SMB repository health

## Status

Implementation in progress on 2026-07-30. This slice is intentionally read-only
and does not claim filesystem health from a successful TCP connection alone.

## Outcome

Docker Dash can register bounded NFS and SMB repository endpoints, reference an
existing encrypted vault secret without returning its value, run real DNS and
TCP probes, retain health history, and alert only on a worsening transition.
Protocol auth/list/write checks use an explicit adapter contract. Without such
an adapter their state is `unknown`, so the repository cannot be reported as
fully healthy.

## API and authorization

| Method | Path | Role | Effect |
|---|---|---|---|
| GET | `/api/storage-repositories` | authenticated | Metadata, last health and bounded history; never secret values |
| POST | `/api/storage-repositories` | admin | Register an endpoint |
| PUT | `/api/storage-repositories/:id` | admin | Version-checked endpoint update |
| DELETE | `/api/storage-repositories/:id` | admin | Delete registry and cascaded observations |
| POST | `/api/storage-repositories/:id/probe` | admin | Run one bounded read-only probe |
| POST | `/api/storage-repositories/:id/write-test` | admin | Adapter-only, opt-in test with typed confirmation and cleanup evidence |

Every mutation and manual probe is audited. The hourly scheduler is leader-only,
bounded to 200 enabled repositories, and never requests a write test.

## Validation and safety

- endpoint is stored as a separate host, port and export/share path;
- URL/UNC credentials, schemes, control characters and `..` path traversal are
  rejected;
- NFS defaults to TCP 2049; SMB defaults to TCP 445;
- private RFC1918 targets are allowed because this is an admin-managed
  infrastructure monitor, but unspecified, multicast and broadcast addresses
  are rejected;
- DNS is resolved once and TCP connects to one returned address, limiting DNS
  rebinding between the two stages;
- response addresses and error codes are bounded; raw socket/system errors and
  secrets are never returned;
- write tests are disabled per repository by default, never scheduled, require
  exact confirmation `WRITE <repository name>`, use a random bounded marker,
  and only succeed when cleanup is explicitly proven;
- cleanup failure is `critical`, even if write/read succeeded;
- no mount, persistent mount, file deletion outside the random marker, provider
  mutation or retention change exists in the built-in adapter.

## Health semantics

- `unavailable`: DNS or TCP failed;
- `unknown`: the network path works but protocol auth/list evidence is absent;
- `degraded`: an adapter reports an auth/list failure or warning latency;
- `healthy`: DNS, TCP, auth and list all pass, and latency is below policy;
- `critical`: latency crossed the critical policy or a write-test marker could
  not be cleaned up.

The first observation establishes a silent baseline. Later worsening transitions
create one system notification and audit event; unchanged failures do not alert
again. History is retained for 180 days.

## Acceptance evidence

- migration, service, route, API, UI and scheduler tests;
- DNS/TCP timeout and output bounds;
- invalid path/credential-shaped input rejection;
- first-baseline and transition de-duplication tests;
- write-test confirmation and cleanup-failure tests through an injected adapter;
- full ESLint, syntax, migration-chain and registry drift checks.

## Remaining before `Done`

  model, then exercise auth/list and opt-in write cleanup against real targets;
- browser smoke test;
- release inclusion and rollout evidence.
