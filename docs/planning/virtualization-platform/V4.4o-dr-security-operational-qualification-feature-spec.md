# V4.4o — DR and security operational qualification

**Status:** implemented for v8.88.0, provider mutations remain fail-closed

**Market features:** B147–B156

## Outcome

The existing operational-qualification endpoint accepts `batch=dr-security`
and returns exactly B147–B156. It reads only local SQLite evidence and release
flags. It does not call a provider registry, open a network connection, start
an external command or dispatch a provider operation.

The response preserves the implementation history: B147–B148 were released in
v8.81.0 and B149–B156 in v8.82.0. v8.88.0 is the qualification release for all
ten and does not relabel any remaining external gap as complete.

## DR evidence facets

| Features | Observed evidence | Deliberate boundary |
|---|---|---|
| B147 | configured protection groups plus planned/unplanned failover rehearsals | no native failover/fencing/cutover |
| B148 | persisted failback rehearsals only | a generic protection group cannot imply failback evidence |
| B149 | persisted `test` rehearsals only | readiness or an enabled flag cannot imply a bubble-network test |
| B150 | runs containing measured RPO or RTO evidence | missing objectives remain unknown/not observed |

Rehearsal counts, success counts and compliance facets are scoped to the
selected primary provider host. `DD_PROVIDER_DR_RUNBOOKS` is reported but never
changed or treated as runtime evidence.

## Security evidence facets

B151 reports versioned pack observations. B152, B153, B154 and B156 count a row
only when its valid JSON facts contain the exact `secureBoot`, `vtpm`,
`encryption` or `confidential` domain. B155 reports non-deleted key-provider
records and separates healthy from degraded/unavailable evidence.

`DD_PROVIDER_SECURITY_ASSURANCE` is returned as a release boundary. A true
flag with no scoped evidence still produces `not_observed`. Secret references,
native provider references and evidence bodies are never returned by this
qualification envelope.

## Response and compatibility

- schema version is additive `1.3`;
- all earlier selectors and their exact ID order are unchanged;
- mixed implementation releases are available per item and as a distinct
  top-level list;

  available and the provider page is exercised.
