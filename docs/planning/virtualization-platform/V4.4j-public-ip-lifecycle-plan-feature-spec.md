# V4.4j — NAT/public-IP lifecycle plans

**Backlog:** B124
**Status:** local planning implementation complete; browser/provider apply/release pending
**Scope:** immutable public-address allocation/mapping/release plans; no apply

## Outcome

Administrators can create deterministic plans for public-IP allocate, map,
unmap and release actions. Plans bind tenant/owner/ownership token, address
family, target mapping, quota, cost, conflict, current allocation state,
optimistic version and provider capability evidence.

## Guardrails

- `allocate` requires quota headroom, clear conflict state and an absent/released
  current allocation.
- `map` requires an allocated public address, explicit private target/protocol,
  expected version and clear conflict evidence.
- `unmap` requires mapped state, the exact target and expected version.
- `release` requires managed ownership, expected version, zero mappings and no
  dependent resources; it cannot silently release an unknown/external address.
- Missing capability, unknown conflict, incomplete checks or impossible current
  state produces `blocked`, never optimistic readiness.
- Hourly cost is stored as integer micros with ISO currency and evidence source,
  avoiding floating-point financial decisions.

## Persistence and UI

- Plans and checks are bounded, immutable and SHA-256 deduplicated.
- Admin-only audited planning endpoint is exposed under Network Advanced.
- UI shows action/state, address/target, owner/tenant, quota, hourly estimate,
  blockers, hash and the zero-apply boundary.

## Safety

- No IP allocation, NAT rule, mapping, unmapping, release, provider call,
  connector call or network mutation is started.
- No credentials or native provider references are accepted.
- Apply belongs to R8 after provider-specific conformance, idempotency,
  post-read, rollback and canary approval.

## Acceptance evidence

- ready allocate/map/unmap/release plans;
- quota, conflict, ownership, version, dependency and mapping blockers;
- IPv4/IPv6 and protocol/port consistency;
- integer cost evidence, strict secrets/limits and dedupe;
- API audit, UI contract, focused tests, lint and registry reconciliation.
