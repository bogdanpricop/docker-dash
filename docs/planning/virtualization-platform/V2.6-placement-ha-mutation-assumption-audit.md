# V2.6 — Assumption audit

| Tempting assumption | Risk | V2.6 control |
|---|---|---|
| an advisory plan is authorization | unreviewed bulk migration | independent stored request and four-eyes approval |
| approval freezes provider state | concurrent changes invalidate intent | complete re-plan at approval and per-child preflight |
| requester and approver may be the same admin | approval theater | database-backed actor separation |
| all providers expose the same HA fields | ignored or destructive settings | writable-field capability matrix and reject-unknown |
| a PVE 8 group is a PVE 9 affinity rule | wrong API/semantics | mutation requires PVE 9+ rule capability |
| standalone ESXi supports cluster rules | invalid SOAP target | vCenter/cluster scope required |
| Xen home server is a mandatory rule | misleading compliance | exposed as preference; XAPI documents higher precedence but not hard enforcement |
| Xen WLB respects VM groups | policy can be breached | plan warning and post-placement evidence |
| vSphere cluster reconfigure can send a full document | accidental reset of unrelated settings | `modify=true`, one incremental spec only |
| a successful HTTP/RPC response proves convergence | provider may apply asynchronously or reject later | durable task reconciliation and live post-read |
| timeout means mutation failed | retry can duplicate or invert change | unknown outcome; never replay after possible submission |
| rollback is replaying the inverse payload | concurrent edits get overwritten | new live semantic plan and approval |
| rebalance rollback is always safe | capacity and workload state change | fresh reverse migration preflight per succeeded item |
| cancelling returns already moved VMs | surprise second mutation | completed moves stay put; rollback is separate |
| parallel candidate choices remain safe at apply time | target overcommit | V2.5 reservations plus V2.2 live preflight before each wave |
| an open maintenance window remains open | operations cross change window | check before every child dispatch; pause at close |
| XO REST mutation is stable because read inventory works | undocumented action drift | XO mutation capability remains unsupported until conformance fixtures and live disposable proof |
| raw Xen can emulate XAPI policy with shell writes | fragile host-specific configuration | raw Xen remains read/limited and fail-closed |
| native identifiers are harmless in approvals | information leakage and replay coupling | canonical IDs in API; native refs encrypted only |
