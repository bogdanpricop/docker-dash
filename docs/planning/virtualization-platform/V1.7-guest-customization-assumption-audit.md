# V1.7 Assumption audit — guest customization

**Audit date:** 26 July 2026

**Decision:** Linux-only structured slice; all unverified transports fail closed

| Assumption | Evidence | Decision |
|---|---|---|
| Proxmox exposes native Cloud-Init configuration | [Proxmox VE Cloud-Init guide](https://pve.proxmox.com/pve-docs/chapter-qm.html#qm_cloud_init) documents Cloud-Init templates and generated configuration | map only bounded QEMU config fields and verify read-back |
| vSphere clone accepts customization | [VirtualMachineCloneSpec](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.vm.CloneSpec.html) defines optional `customization` and exact WSDL order | embed LinuxPrep in the clone spec |
| vSphere can validate before disk copy | [VirtualMachine.CheckCustomizationSpec](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.VirtualMachine.html) explicitly checks source compatibility before clone | mandatory precheck |
| LinuxPrep supports selected identity fields | [CustomizationLinuxPrep](https://developer.broadcom.com/xapis/vsphere-web-services-api/latest/vim.vm.customization.LinuxPrep.html) defines hostname, domain, timezone and hardware-clock semantics | no passwords or scriptText; user/SSH keys blocked |
| XO can create a VM with Cloud-Init through REST | official XO [pool controller](https://github.com/vatesfr/xen-orchestra/blob/master/%40xen-orchestra/rest-api/src/pools/pool.controller.mts) defines async `create_vm`; [pool types](https://github.com/vatesfr/xen-orchestra/blob/master/%40xen-orchestra/rest-api/src/pools/pool.type.mts) include `cloud_config`, `network_config` and config-VDI controls | discover Swagger route and fields before enabling |
| XO Cloud-Init is intended for template instantiation | [XCP-ng cloud documentation](https://docs.xcp-ng.org/management/cloud/) describes first-boot hostname, SSH-key and user configuration from compatible templates | render NoCloud-style structured YAML only |
| direct XAPI has equivalent portable upload semantics | no verified official high-level config-drive upload contract was found in the selected XAPI surface | unsupported; recommend XO endpoint |
| B040–B047 identify guest customization | research table maps B040–B047 to image import/versioning/TTL/schedules/guest-tool operations | correct V1.7 to B035; B036 remains profile work |

## Version caveats

- Proxmox template compatibility is runtime-dependent; capability remains conditional.
- vSphere Linux guest support and installed guest components are validated by the server, not inferred locally.
- XO is enabled only on deployments whose current Swagger advertises the exact route and request fields.
- legacy raw `xl/xm` is not expanded with filesystem/SSH injection.
