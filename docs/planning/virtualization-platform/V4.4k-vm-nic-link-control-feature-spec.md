# V4.4k — Controlled VM NIC link state

**Backlog:** B104
**Status:** local implementation complete; browser/provider canary/release pending
**Scope:** connect/disconnect an existing VM NIC; never attach, detach, delete or remap

## Outcome

Administrators can inspect live normalized NIC inventory, declare short-lived
disconnect safety evidence, run a hash-bound preflight, and queue a durable
connect or disconnect operation. Provider state is re-read before submission
and after completion.

## Provider boundary

- Proxmox VE edits only the selected existing `netN` configuration value and
  changes `link_down`, preserving the other fields and binding the write to the
  provider configuration digest when one is available.
- VMware vSphere submits `ReconfigVM_Task` with an `edit` operation for the
  existing virtual Ethernet device and changes only
  `VirtualDeviceConnectInfo.connected`; `startConnected` and
  `allowGuestControl` are preserved when observed.
- XenAPI submits only `Async.VIF.plug` or `Async.VIF.unplug` after checking the
  current VIF record and allowed operations.
- Xen Orchestra and raw Xen remain unsupported for mutation because no
  conformance-tested task-safe link contract is available.

## Disconnect safety

- Current link state and `connectDisconnect=true` must be positive provider
  evidence; unknown never becomes allowed.
- The last connected NIC cannot be disconnected.
- An admin must declare `non_management`, `boot_dependency=not_required` and
  `guest_dependency=not_required`, with a reason and validity of at most four
  hours by default.
- The declaration is bound to a SHA-256 fingerprint of canonical VM/NIC ID,
  device, MAC, model and network/VLAN identity. A hardware or network mapping
  change invalidates it.
- Safety expiry, fingerprint, current link state, provider release flag and
  last-NIC evidence are revalidated in the worker immediately before mutation.

## Operation semantics

- Preflight binds capability, policy, permission, active-operation conflict,
  current/desired state, safety evidence, confirmation text and expiry into a
  deterministic plan hash.
- Submission requires admin role, host operate access, writeable mode,
  idempotency key and exact typed `VM/NIC` confirmation.
- VM and NIC device scopes are locked for the non-retryable operation.
- Native task references stay encrypted in the common operation engine;
  synchronous and asynchronous providers both require post-read verification.
- Ambiguous timeout produces `unknown` plus a manual rollback plan. Rollback is
  never automatic and requires a fresh preflight.

## Release controls

Each adapter is default-off and independently released:

- `DD_PROVIDER_VM_NIC_LINK_PROXMOX`
- `DD_PROVIDER_VM_NIC_LINK_VSPHERE`
- `DD_PROVIDER_VM_NIC_LINK_XEN`

`DD_PROVIDER_VM_NIC_SAFETY_MAX_HOURS` and
`DD_PROVIDER_VM_NIC_VERIFY_TIMEOUT_MS` bound evidence validity and
post-verification.

## API and UI

- live NIC inventory and safety state under the canonical VM route;
- admin-only audited safety declaration;
- admin-only audited preflight and durable action submission;
- Network tab actions show release/capability state, declaration state,
  blockers, exact mutation boundary and Activity Center link.

## Acceptance evidence

- missing/expired/unsafe/hardware-changed declarations block disconnect;
- the last connected NIC is blocked at preflight and execution;
- connect does not require a disconnect declaration but still requires policy,
  capability, release and typed confirmation;
- provider clients issue link-only calls and never remove a device;
- synchronous and asynchronous operations are post-read verified;
- routes, audit, UI, catalog, migration and focused tests are present.
