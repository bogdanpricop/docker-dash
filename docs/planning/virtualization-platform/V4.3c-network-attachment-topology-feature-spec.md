# V4.3c — VM network attachment topology feature specification

**Status:** planned for v8.30.0 (2026-07-28)

`GET /api/providers/:hostId/network-attachment-topology` groups provider-visible
VM NIC attachments by a host-scoped opaque network identity. It requires
`network.attachmentTopology.read`, reads at most 100 VMs with four concurrent
hardware reads, and reports coverage when NIC inventory is unavailable or
truncated. Provider-native network identifiers never leave the server.

The projection is read-only. It is attachment evidence only: it does not prove
routing, firewall policy, traffic flow, connectivity or tenant isolation. It
does not query guests, send traffic, change NICs/VLANs/switches, use CLI fallback
or provide remediation. Initial support is conditional for vSphere and Xen;
Proxmox remains unsupported pending a common safe network-inventory contract.
