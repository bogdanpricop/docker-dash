# V0.1 Feature spec — Provider SDK v2 și capability contract

## Problemă

Capabilitățile sunt definite astăzi în mai multe locuri: `docker.js`, clienții providerilor și paginile frontend. Formatul diferă, iar valorile sunt adesea statice. UI-ul nu poate distinge între „vendorul nu suportă”, „ediția nu suportă”, „endpoint-ul nu a fost probat” și „conexiunea este temporar indisponibilă”.

## Outcome

Un endpoint comun și o bibliotecă internă versionată descriu ce poate face fiecare endpoint. Primul slice acoperă Proxmox, vSphere și Xen fără a modifica încă operațiile lor.

## User stories

1. Ca operator, văd capabilitățile reale ale endpoint-ului și motivul indisponibilității.
2. Ca frontend developer, folosesc aceleași chei pentru VM/host/storage/network/task pe toți providerii.
3. Ca provider implementer, înregistrez un adaptor și trec același conformance test.
4. Ca auditor, disting capabilități declarate static de cele confirmate live.
5. Ca administrator, pot forța un refresh fără a expune credențiale sau native refs.

## Scope

- Provider SDK internal v2, fără plugin loading extern.
- Schema versionată `1.0` pentru provider descriptor și capability evidence.
- Catalog inițial de chei neutre.
- Registry/adapters pentru `proxmox`, `vsphere`, `xen`.
- Endpoint authenticated, host-scoped.
- Cache bounded și invalidare la update/delete/reconnect.
- Conformance tests și fixtures.
- Compatibilitate cu forma legacy din `/api/system/info`.

## Anti-scope

- common resource model complet;
- mutations noi;
- task engine persistent;
- marketplace/plugin sandbox;
- dynamic package loading;
- UI VM detail;
- feature parity declarată pentru funcții neprobate.

## API propus

`GET /api/providers/:hostId/capabilities`

Query:

- `refresh=true` — admin-only, ignoră cache-ul;
- fără `refresh` — folosește evidence cache până la TTL.

Envelope abreviat:

```json
{
  "schemaVersion": "1.0",
  "provider": {
    "type": "xen",
    "variant": "xapi",
    "product": "XCP-ng",
    "version": "8.x",
    "apiVersion": "xapi",
    "endpointId": 7,
    "endpointName": "pool-a"
  },
  "probe": {
    "status": "reachable",
    "checkedAt": "2026-07-26T12:00:00.000Z",
    "cached": false,
    "error": null
  },
  "features": {
    "vm.read": {
      "state": "supported",
      "source": "live",
      "reason": null,
      "constraints": {}
    },
    "vm.console": {
      "state": "unsupported",
      "source": "adapter",
      "reason": "Not implemented by the Docker Dash adapter",
      "constraints": {}
    }
  }
}
```

## Capability states

| State | Semnificație |
|---|---|
| `supported` | endpoint-ul și adaptorul pot furniza funcția |
| `conditional` | disponibilă numai în condiții/ediții/backend-uri descrise |
| `unsupported` | confirmat indisponibil la endpoint sau în adaptor |
| `unknown` | nu există evidence suficient ori proba a eșuat |

`source` poate fi `live`, `adapter`, `version`, `configuration` sau `fallback`.

## Catalog inițial

- `inventory.vm`, `inventory.host`, `inventory.cluster`, `inventory.storage`, `inventory.network`, `inventory.task`;
- `vm.read`, `vm.power.start`, `vm.power.shutdown`, `vm.power.force`, `vm.power.reboot`;
- `vm.snapshot.list`, `vm.snapshot.create`, `vm.snapshot.revert`, `vm.snapshot.delete`;
- `vm.console`, `vm.clone`, `vm.create`, `vm.migrate`;
- `host.maintenance`, `cluster.ha.read`, `storage.mutate`, `network.mutate`;
- `task.read`, `task.cancel`, `task.cleanup`, `event.stream`, `backup.read`, `backup.run`.

Catalogul este aditiv. O cheie nu își schimbă sensul după publicare.

## RBAC

- orice utilizator autentificat cu access la host poate citi forma cached;
- `refresh=true` necesită `admin`;
- endpoint-ul nu returnează config, credential presence, native refs sau raw provider errors;
- host scope este verificat prin middleware-ul comun.

## Audit

- citirea cached nu produce audit noise;
- refresh manual produce `provider_capability_refresh` cu host ID, provider, status și durată;
- credentialele și endpoint URL complet nu intră în details.

## Acceptance criteria

1. Proxmox, vSphere și Xen emit schema `1.0` validă.
2. Fiecare feature are state/source/reason/constraints.
3. Un endpoint unreachable returnează descriptorul safe, `probe.status=unreachable` și evidence `unknown` unde este necesar.
4. Cache-ul este invalidat la host update/delete și reconnect.
5. Refresh-ul admin bypass-ează cache-ul; non-admin primește 403.
6. Host access și tenant scope existente sunt respectate.
7. Niciun secret, native ref sau stack trace nu este expus.
8. Conformance suite respinge keys necunoscute, state invalide și envelope fără timestamp.
9. `/api/system/info` rămâne backward-compatible.
10. Testele includ auth failure, timeout, stale cache, provider variant și partial capability.

## Feature flag și rollout

`DD_PROVIDER_SDK_V2=true` controlează endpoint-ul în prima versiune. Default-ul poate fi `true` în development/test și `false` în production până după primul deploy canary. Eliminarea flag-ului se face după două batch-uri fără schema break.
